# ADR 0004 · 沙箱与真实集成（设计，M1 未实现）

- 状态：提议（Proposed）——**仅设计，代码未实现**
- 日期：2026-11-04
- 关联：`docs/simulation/09_feasibility_risks.md`（风险 2/3）、`docs/design/04`（编程线）、`docs/curriculum/04-programming-track.md`

## 1. 背景

两件事在本作里都必须"真做"，但都**不能**放在游戏进程里真做：

1. **玩家的代码要能跑**：编程线要求汇编 / C / Java / Python 在游戏内被编译执行，结果回显。
2. **L7 真实主机桥接**：最后一关要让玩家写的协议真的收发数据（UDP / 串口 / 本机端口）。

游戏进程里跑玩家代码的后果是明确的：死循环卡死主线程、`rm -rf` 毁掉玩家目录、内存爆炸、弹窗/进程泄漏，
以及最糟的一条——**把不确定的宿主环境塞进"确定性仿真"**（`docs/simulation/02` 明确禁止）。

因此这里写成一组**硬规则**；M1 范围克制在 L0–L1（`specs/m1/spec.md` §8 已把沙箱列为"仅 ADR 设计"）。

## 2. 决策（设计约束，实现待 M3+）

### 2.1 进程隔离：子进程 + 资源约束

| 项 | Windows | Linux（如未来支持） |
|---|---|---|
| 隔离单元 | **Job Object**（`CreateJobObject` + `AssignProcessToJobObject`） | **cgroup v2** 单层级组 |
| 可执行 | 独立 `ifz_sandbox.exe`（游戏只通过 stdin/stdout 的 JSONL 协议通信） | 同左 |
| 超时 | Job 级 `JOB_OBJECT_LIMIT_PROCESS_TIME`（CPU 时间）+ 游戏侧 wall-clock 超时（默认 3 s 编译 / 5 s 运行，**假设**） | cgroup CPU 配额 + 侧置定时器 |
| 内存上限 | `JOB_OBJECT_LIMIT_PROCESS_MEMORY`（默认 256 MB，**假设**） | `memory.max`（同值） |
| 进程数 | `JOB_OBJECT_LIMIT_ACTIVE_PROCESS = 1`（禁 fork 轰炸） | `pids.max = 1` |
| 崩溃 | Job 关闭即杀整棵树（`TerminateJobObject`），不留孤儿 | 组内 `cgroup.kill` |
| 优先级 | `IDLE_PRIORITY_CLASS` | `cpu.weight` 最低档 |

- 通信协议：逐行 JSON（请求 `{op:"compile"|"run", ...}`，响应 `{ok, code, stdout, stderr, ms}`），**只走进程标准输入输出**，不共享文件句柄。
- 超时/超限一律回报 `IFZ_E_LIMIT`-类错误码（编号留给原生错误表，见 ADR 0002 §2.2），并在 UI 明示"被沙箱终止"。

### 2.2 文件与网络：只读挂载 + 白名单

- 文件系统：沙箱只挂**只读**的编译器/解释器与标准库目录；玩家可写的只有一个**临时目录**（每次运行新建、运行结束删除）。
  - **白名单路径**：只允许读 `<install>/tools/<lang>/**`、`<temp>/proj/**`；其余一律拒绝（不靠"过滤字符串"，靠挂载/句柄能力）。
  - 禁止访问：`user://saves`（存档目录）、游戏安装目录可写区、用户主目录、系统目录。
- 联网：默认**禁网**。Windows 用 Job 无法直接禁网，需配合防火墙规则或"无网络能力令牌"；Linux 用 network namespace。
  任何需要联网的教学内容必须显式声明并走 2.3 的转发路径。
- 输入输出限额：单次运行 stdout ≤ 64 KB、总输出行 ≤ 2000（**假设**），超出截断并标注"已截断"。

### 2.3 L7 真实主机桥接：必须显示「转发」

- 结构：游戏内虚拟网卡（L6 教学协议）→ **伴生进程**（本地 socket）→ 真实端口。
  `docs/simulation/01` §9 已定义：这是 **proxy**，不是"游戏内跑真 TCP/IP"。
- **UI 硬规则**：凡走桥接的数据，界面上必须有常驻「转发」标记（与"教学协议"标记并列显示端口与方向），
  抓包器里真实链路的帧必须标注"由系统协议栈处理，游戏内不实现也不验证"。
- **文案禁词**（`docs/simulation/09` 风险 2/3）：禁止出现"你写的协议已在公网运行""你在用真实 TCP""游戏内加密是安全的"。
  允许表述："你的协议通过本机伴生进程转发到一个真实端口；真实链路用的是系统协议栈。"
- 加密同理：需要"安全通信"时经桥接调用宿主标准库（TLS），UI 标注"此段由宿主提供，游戏内只做转发"。

### 2.4 跨模块铁律

1. 仿真线程**不做**任何进程/文件操作（`docs/simulation/07` §7）；沙箱调用只发生在主线程的"显式动作"（点"运行"）。
2. 沙箱运行**不得**写仿真状态：结果只作为"采集到的观测值"交给判定层（`LabChecks` 风格），与 `SimCircuit` 解耦。
3. 任何沙箱结果进入教学判定前，必须能被"离线重放"（同样输入 → 同样输出摘要），否则不算确定性证据。

## 3. 后果

- 正面：玩家代码崩溃不带走游戏；课程可以放心让学生写死循环。
- 代价：要维护沙箱宿主（编译/运行两条链路）、每种语言的工具链版本、以及各平台的资源限额实现；Windows 与 Linux 的限额语义不同，需要两套测试。
- 教学影响：`docs/simulation/09` 已明确"真 TCP/真加密"不做，因此桥接只用于"对照实验"，不用于主线判定。

## 4. 备选方案与否决理由

| 方案 | 结论 | 理由 |
|---|---|---|
| **进程内解释器（嵌 Python/JS）** | 否决 | 无隔离：死循环卡死主线程，异常可篡改进程状态；内存与文件权限无法约束 |
| **WASM 沙箱（wasmtime/wasm3）** | **保留**（备选） | 天然无 syscall、可限内存与指令数、跨平台一致；否决为"当前方案"的理由：需要为每种语言准备 WASM 工具链（C/Java 交叉编译链不成熟），且汇编/裸机教学无法在 WASM 里演示真实 ABI |
| **Docker / 容器** | 否决 | 不能要求玩家安装 Docker；Windows 上依赖 WSL2 与虚拟化，教育场景不成立 |
| **真虚拟机（QEMU/Hyper-V）** | 否决（M1–M3） | 包体、启动时间、授权与图形集成成本过高；L0–L4 不需要真实内核 |
| **直接在主进程 `OS.execute` 跑编译器** | 否决 | 没有资源限额等于把机器交给学生代码；`OS.execute` 无 Job 能力 |
| **只做"模拟运行"（不真执行）** | 否决 | 与教学承诺冲突：编程线的价值就在于"我的代码真的跑了"；但可作为沙箱不可用时的**降级**并在 UI 标注"未真执行" |

## 5. 本里程碑（M1）的实际状态

- **未实现**：无沙箱、无编译器桥接、无 L7 伴生进程、无资源限额、无禁网规则。
- 已在文档中固化的只有：UI 的「转发」标记要求、"禁止声称真实 TCP/安全加密"的文案规则、错误必须显式上报的约定。
- 待办（需人工）：确定沙箱宿主语言与首发语言清单、确定限额默认值（现为假设）、建立"沙箱逃逸"回归用例集。

## 6. 复审触发条件

1. 编程线进入 M3（需要真编译）→ 先把沙箱宿主与限额落地，再接任何关卡。
2. 决定支持 Linux 分发 → 补 cgroup v2 实现与跨平台测试。
3. 出现 WASM 工具链成熟的 C/汇编方案 → 重评 4 中的"保留"项。
