# 01 分层模型（Simulation Layer Model）

本文件定义仿真的**八层模型**与层间契约。所有层都在同一时间基（整数 tick）上推进，
但**推进方式**不同：组合层是事件驱动，时序层是时钟边沿驱动，网络层是收发事件驱动。
不允许出现"某一层用浮点时间、另一层用帧数"的混搭。

## 0. 总览

| 层 | 名称 | 保真度 | 时间推进 | 状态规模（单场景上限） |
|---|---|---|---|---|
| L0a | 模拟电平（可选） | 简化 RC | 固定步长（子 tick） | 64 个节点以内 |
| L0b | 数字电平 / 信号 | 全保真（数字域） | 事件驱动 | ≤ 3 万根线网（单场景） |
| L1 | 门级 | 全保真（门级 + 归一化延迟） | 事件驱动（传输/惯性延迟） | ≤ 200 门（GDScript）/ ≤ 1 万门（原生，60 FPS） |
| L2 | 组合电路 | 全保真（结构级） | 事件驱动 + 稳定判定 | 由 L1 组合而成，单模块 ≤ 2000 门 |
| L3 | 时序电路 | 全保真（边沿 + 建立/保持） | 时钟边沿驱动 | ≤ 200 / 8000 触发器 |
| L4 | 寄存器/ALU/CPU | 结构级数据通路 + 微码控制 | 时钟驱动（周期精度） | 单 CPU + 64 KiB 空间 |
| L5 | 总线 / IO | 协议级（握手、仲裁、三态） | 事件驱动（周期内多相位） | ≤ 16 个主设备 |
| L6 | 网络 | 简化协议栈（见 04） | 事件驱动（毫秒 tick） | ≤ 256 节点 / 4096 包在途 |
| L7 | 真实主机桥接 | **代理**（不宣称全保真） | 宿主 socket | 1–4 个连接 |

> 交付口径：**8 个主层**（L0–L7），其中 L0 拆成 L0a/L0b、L6 拆成 L6a/L6b/L6c，
> 共 **11 个子层**。L0a 与 L7 是"可关闭"的，关闭后不影响教学主线。

## 1. L0a 模拟电平（可选层，明确标注为简化）

**为什么存在**：玩家第一次接触"电"时，需要看到电压连续变化、看到阈值、看到 RC 充放电，
否则"0/1"会像魔法。但全场景模拟 RC 网络代价极高，所以只在**教学沙盘**里开启。

- 状态：每个节点 `{voltage_mV: int, capacitance_fF: int}`；电源 `VDD=1000mV`（演示用归一电压）。
- 输入：驱动源（理想阶跃 / 带内阻）。
- 输出：各节点电压、阈值判决结果（`>600mV → 1`，`<400mV → 0`，中间 → X）。
- 推进：固定子步长 `dt = 1 tick / 16`，显式 Euler 积分。
- 可观测点：示波器（电压-时间曲线）、阈值线、门延迟成因标注。
- **简化声明**：不做真实器件方程（无 MOS 平方律、无温度、无噪声）；RC 时间常数是
  手工设定值。它解释"为什么有延迟"，**不能**用来推算真实芯片频率。
- 关闭条件：场景离开"晶体管/电平"教学关后强制关闭，避免玩家以为其余层也是模拟量。

## 2. L0b 数字电平 / 信号

- 状态：位串 `bits ∈ {'0','1','X'}*`，X 表示未知/竞争/亚稳态，**不是第三路电平**。
  高阻 `Z` 不在此层表达；总线上的 Z 由 L5 的"驱动使能"显式建模（未驱动 = 该线不被写）。
- 输入：外部驱动、上游模块输出。
- 输出：下游门的输入、探针。
- 推进：事件驱动；一次写入即一次事件，按 `(tick, seq)` 全序处理。
- 可观测点：探针值、变化历史（tick, wire, 旧值, 新值）、毛刺计数。
- 关键约定：**任何 X 都必须能被下游看见**，禁止"遇到 X 就当 0"。

## 3. L1 门级

- 状态：门实例 `{kind, inputs[], output, delay, model}`。
- 输入/输出：见 03 的器件表。
- 推进：**传输延迟 + 惯性过滤**（见 02 第 4 节）。输入变化 → 在 `t+delay` 求值；
  求值时读"当前"输入值，因此窄于门延迟的脉冲被滤除（与真实 CMOS 一致）。
- 延迟表（归一化，1 tick = 1 个反相器延迟）：

  | 门 | not/buf | nand/nor | and/or | xor | xnor |
  |---|---|---|---|---|---|
  | tick | 1 | 2 | 3 | 4 | 5 |

  > 这些数字是**归一化比例**，不是某工艺库的真实值。文档里任何"频率/延迟换算"都必须标注"教学单位"。
- 可观测点：每根线网、每个门的输入输出快照、事件计数、单 tick 事件上限触发告警。
- 错误行为：位宽不匹配 → 构建期报错；组合环 + 零延迟 → `SimLimitExceeded`；
  未知输入 → X 传播（Kleene 逻辑，`X AND 0 = 0`，`X OR 1 = 1`）。

## 4. L2 组合电路

- 状态：由门组成的模块（半加器、全加器、加法器、选择器、译码器、比较器）。
- 契约：**稳定时间上界**（settling bound）。每个模块必须给出 `t_settle`，
  例如 8 位行波加法器 `t_settle = 6n = 48 tick`（实测 48，见 08）。
- 推进：事件驱动；`settle()` 跑到队列空。
- 可观测点：模块级输入/输出、逐级内部节点（进位链）、稳定时间。
- 禁止：把"模块"实现成"直接返回正确结果、延迟填常数"的黑盒而不给出结构 → 那是假仿真。
  允许黑盒（如 ALU 的加法部分）**仅当**延迟由结构推导且给出等价性测试。

## 5. L3 时序电路

- 状态：触发器集合、时钟相位、异步复位。
- 输入/输出：D、CLK、RESET、Q。
- 推进：上升沿采样；采样前检查建立时间（默认 2 tick），边沿后检查保持时间（默认 1 tick）。
- 违例行为：Q 在 `clk_to_q` 后变成 **X**，并在 trace 里写 `METASTABLE`；
  下一个正常边沿把 X 覆盖掉。**绝不静默采到错误但确定的值**。
- 可观测点：CLK/Q 波形、METASTABLE 事件、每个寄存器的采样时刻。
- 教学价值：时钟周期 < 组合延迟时，玩家会亲眼看到 X 出现（参考实现里 period=10 < 31 即复现）。

## 6. L4 寄存器 / ALU / CPU

- 状态：PC、IR、ACC、标志位（Z/C/V/N）、寄存器堆、存储器内容。
- 输入/输出：指令流、数据、时钟。
- 推进：微码状态机，每个状态固定 `ticks`；周期精度，不做门级展开。
- 微码表（与 `ref/simcore/components.py` 同源，实现必须复制这张表而不是另写）：

  | 状态 | 断言信号 | 下一状态 | tick |
  |---|---|---|---|
  | S_FETCH_MAR | MAR_PC | S_FETCH_R | 1 |
  | S_FETCH_R | MEM_R | S_FETCH_IR | 10 |
  | S_FETCH_IR | IR_IN | S_FETCH_PC | 2 |
  | S_FETCH_PC | PC_INC | S_DECODE | 2 |
  | S_DECODE | DECODE | S_EXEC | 1 |
  | S_EXEC | ALU_OP, REG_W | S_FETCH_MAR | 2 |

- 可观测点：每周期寄存器快照、PC、指令反汇编、ALU 标志。
- 简化声明：不做流水线、不做乱序、不做 cache；CPU 位宽 8/16 可配，但指令周期固定。

## 7. L5 总线 / IO

- 状态：总线占用者、驱动使能、握手相位（REQ/ACK/READY）、外设寄存器。
- 输入/输出：主设备发起、从设备响应、中断线。
- 推进：事件驱动，**相位内可有多事件**；总线仲裁（固定优先级，可配轮询）。
- 可观测点：总线波形（地址/数据/控制）、冲突计数、等待周期数。
- 错误行为：两个主设备同时驱动 → BUS_CONTENTION（总线值变 X，且记事件）；
  从设备无响应超时 → 超时计 N tick 后返回 ERR_NO_ACK。
- 简化：不做电气反射/串扰；总线宽度固定；无 DMA。

## 8. L6 网络（三个子层）

### L6a 链路 / 帧
- 状态：MAC 地址表（点到点链路上只有对端）、帧队列。
- 帧：`{dst_mac, src_mac, ethertype, payload, fcs(CRC-8)}`。
- 推进：事件驱动；链路延迟、丢包率、误码率（翻位后用 FCS 检出）。
- 可观测点：抓包器（帧序、CRC 校验结果）、线缆上的比特流。

### L6b 网络 / 路由
- 状态：IP 地址、ARP 缓存、路由表（`dst_ip → next_hop_ip`）、TTL。
- 推进：事件驱动；每跳 `+= link_delay`。
- 可观测点：路由表（含来源：静态/链路状态/距离矢量）、逐跳路径、TTL 递减。
- 简化：只实现 /24 与 Dijkstra 链路状态；距离矢量仅作"计数到无穷"的对照实验。

### L6c 传输 / 可靠
- 状态：连接状态机（SYN_SENT/ESTABLISHED/FIN_WAIT...）、`next_seq`、`acked`、RTO。
- 推进：事件驱动；超时是定时器事件，不是"每帧检查"。
- 可观测点：时序图（segment/ack/RTO）、重传计数、退避曲线。
- 简化：段编号而非字节编号、无拥塞控制、无乱序缓存，详见 04。

## 9. L7 真实主机桥接（明确不保真）

- 目的：最后一关"接真实电脑"，让玩家用自制协议真的收发数据。
- 实现：宿主侧伴生进程（本地 UDP/串口）+ 游戏内虚拟网卡；**不是**在游戏里跑真 TCP/IP。
- 状态：连接句柄、字节缓冲、超时。
- 可观测点：收发字节、延迟、丢包。
- **诚实边界**：这是代理（proxy），游戏内协议栈与真实内核协议栈是"语义对齐"而非"实现相同"。
  任何"你写的协议已在公网运行"的文案都必须改成"通过伴生进程转发到本机端口"。

## 10. 层间契约（必须固定）

| 相邻层 | 传递什么 | 不允许传递什么 |
|---|---|---|
| L0a→L0b | 阈值判决后的 0/1/X | 连续电压值（数字层不得读 mV） |
| L0b→L1 | `wire_id + bits` | 门内部实现细节 |
| L1→L2 | 模块端口位串 | 门的实例顺序（会破坏重排优化） |
| L2→L3 | 稳态输出（已 settle） | 未稳定的中间值（除非显式开启"冒险观察模式"） |
| L3→L4 | 寄存器值、时钟边沿 | 触发器的 X 传播路径（CPU 层只能看到"采样失败"标志） |
| L4→L5 | 总线事务（addr/data/we） | 机器周期内部相位 |
| L5→L6 | 帧字节流 | 总线时序 |
| L6→L7 | 应用字节流 | IP 包内部字段（桥接层不解析游戏协议） |

**跨层一致性策略**：每一层都必须有一套**等价性测试**（同一输入，层 A 的结果 == 层 B 的
抽象结果）。例如 L1 的 8 位加法器与 L4 的 ALU 加法，必须在 256×256 组合上一致（08 里有这条）。

## 11. 可观测点的统一约定

所有层都通过同一个 `TraceSink` 上报，字段固定：

```
(tick:int, layer:"L0b"|"L1"|..., kind:str, subject:str, payload:json)
```

`kind` 的取值域固定为：`CHANGE`（值变化）、`EDGE`（时钟/握手边沿）、`DROP`（丢弃）、
`ERR_*`（错误）、`SAMPLE`（采样/判决）。UI 的示波器、抓包器、时序图都只消费这个流，
不允许各层自己往 UI 里塞数据 —— 否则回放会不一致。

## 12. 本层模型的已知缺口

1. 没有模拟"线的电容/串扰"，所以高频下的信号完整性问题无法演示（只做 L0a 教学沙盘）。
2. 没有多驱动强度模型（只有"驱动/不驱动"），总线争用只表现为 X + 事件。
3. 没有功耗/发热模型，因此"降频省电"这类关卡不能做真实计算。
4. 网络层是"理想链路 + 注入丢包"，没有真实无线信道模型（不做衰落/干扰）。
