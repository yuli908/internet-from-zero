# 04 网络规格（帧 / 路由 / 转发 / 可靠传输）

对应实现：[network.py](file:///D:/ai%20lm/internet_from_zero/docs/simulation/ref/simcore/network.py)。
本文件的所有数字都来自实际运行（见 [verify_report.md](file:///D:/ai%20lm/internet_from_zero/docs/simulation/ref/verify_report.md)），
不是推导出来"应该如此"的理想值。

## 0. 一句话立场

网络层是**教学用的简化协议栈**，不是协议实现。它保证"玩家能亲眼看到逐跳、丢包、重传、
计数到无穷"，但它**不保证与真实 TCP/IP 逐字节兼容**。所有简化在第 7 节集中列出，
并逐条写清对教学结论的影响。

## 1. 地址与命名空间

| 对象 | 本规格 | 真实世界 | 差异处理 |
|---|---|---|---|
| MAC | `u8`（2 位十六进制，如 `0x0a`） | 48 位 | 教学用 8 位；仅用于点对点链路的"这一段是谁"，不承载语义 |
| IP | 完整 `u32`（点分十进制显示） | 32 位 | **不缩减位宽**，避免"IP 只有 4 位"的错误直觉 |
| 子网掩码 | 只支持 `/24` | VLSM/CIDR | 不做子网划分教学；跨网段只出现在预设拓扑 |
| 端口 | `u8` | 16 位 | 仅用于多路复用演示，不实现端口范围语义 |
| 段编号 | 从 1 递增的整数（**按段**，非按字节） | 字节序号 | 关键简化，见 7.3 |
| 路由 metric | 跳数 | 跳数/带宽/延迟 | 只教"跳数"这一种 |

地址分配是**场景固定**的（由关卡数据给出），不做 DHCP、不做 NAT、不做动态主机配置。

## 2. 帧（L6a）

```
+--------+--------+----------+---------+--------+
| dst_mac| src_mac| ethertype| payload | fcs    |
|  8 bit |  8 bit |  16 bit  |  N byte | 8 bit  |
+--------+--------+----------+---------+--------+
```

- `ethertype`：字符串枚举 `IPv4 / ARP / IPv4-FRAG`（教学枚举，不追求 IANA 数值一致）。
- `fcs` = **CRC-8**（多项式 `0x07`，初值 0，无反射）。计算范围 = `dst|src|ethertype|payload`。
- 收端必须**用收到的 fcs 字段做校验**，禁止"收到就重算一遍再比"（那等于没校验）。
  参考实现为此把 `fcs` 做成帧的独立字段，并在链路噪声里"翻位但不改 fcs"，
  实测 104 组单比特错误**全部检出**（104/104）。
- **诚实标注**：真实以太网 FCS 是 CRC-32，且还有前导码、IFG、最小帧长 64 字节。
  CRC-8 只能证明"能抓到坏帧"，**不能**外推为真实链路的误码检出力。
- 链路是**点对点**的（`Link{a,b,delay,loss,corrupt}`），**没有**广播域、CSMA/CD、交换机转发表。
  因此"共享介质冲突"这一课在本规格内**不做**（见 09 的替代方案）。

推进：事件驱动。一次发送 = `now += link.delay`（传输延迟，单位毫秒 tick）；
丢包与误码在**发送点**一次性判定（先丢包，再误码，顺序固定）。

## 3. ARP（L6b）

教学目标只有一个：**"知道 IP 还不够，还得知道下一跳的硬件地址"**。

| 步骤 | 行为 | 延迟 |
|---|---|---|
| 1 | 查 ARP 缓存命中 → 直接返回 MAC | 0 |
| 2 | 未命中 → 发 `ARP_REQ`（广播语义在点对点链路上退化为"发给对端"） | +2 |
| 3 | 收 `ARP_REP` → 写入缓存 | 0 |
| 4 | 缓存项老化 | 本规格**不做**（记为缺口） |

- 一次 `send()` 里 `resolve()` 可能让 `now` 前进 2 tick，必须计入时序图，不能"免费"。
- 简化：点对点链路没有广播，所以 ARP 是"一问一答"而不是"广播 + 多收方"；
  没有 ARP 欺骗、没有代理 ARP、没有免费 ARP。
- 教学影响：玩家能理解"缓存"和"下一跳"的必要性，但**学不到**广播域与 ARP 欺骗
  （这两点必须在剧情/文档里显式说明"本游戏未模拟"）。

## 4. 路由表与最短路（L6b）

### 4.1 链路状态（主方案）

- 每个节点持有拓扑（邻接 + 链路代价），用 **Dijkstra** 计算到所有目的地的下一跳。
- **确定性要求**：平局（等代价）按 **IP 升序** 选，禁止按插入顺序或哈希顺序。
  参考实现用朴素 O(V²) 扫描（`min(key=(dist, ip))`），节点上限 256，代价可接受，
  且天然规避堆的平局不确定性。
- 表结构：`routes: {dst_ip -> next_hop_ip}`（存**下一跳**，不存整条路径；
  整条路径只在 UI 上按需展开，不进入状态）。
- 实测：5 节点 6 链路拓扑，全表 **12 条** 路由（5×4 非自身项），`A→C` 代价 **4**；
  与独立的 Floyd 最短路逐项一致（不是"自己验自己"）。
- 断链重收敛：断掉 A–B 后 `A→C` 由 **4 → 5**（绕行），在下一轮拓扑更新后立即生效。
- 收敛判据：一次 `compute_routes()` 即得收敛表（集中式计算）。
  这**不是**分布式收敛，见 4.2 与 7.4。

### 4.2 距离矢量（对照实验，只为演示"坏消息传得慢"）

- metric = 跳数，**16 = 无穷**（真实 RIP 是 16，这里沿用；IPv4 TTL 的 255 不用在这里）。
- 语义必须包含三条，否则复现不出计数到无穷：
  1. **同一邻居通告的"同路径"路由，即使变差也必须替换**（这是根因）；
  2. 有毒逆转（split horizon with poisoned reverse）：把"从该邻居学到的目的地"以 16 回传；
  3. 事件驱动（不是同步轮次）。断链瞬间，邻居的**旧通告还在飞**——这正是真实网络的行为。
- 实测（断 A–B，观察 `A→C`）：
  - 无水平分割：`2 → 4 → 6 → … → 16`（**计数到无穷**，共 16 步后才稳定）；
  - 有水平分割/毒性逆转：`2 → 16`（只坏一次就收敛）。
- 教学价值：这两条曲线的对比就是"为什么需要水平分割"的全部论据。
- **明确不做**：BGP、策略路由、ECMP（ECMP 会让"选哪条"不确定，与确定性要求冲突）、
  路由聚合、认证。

## 5. 分组转发（L6b）

`send(src, dst, payload, proto, ttl=8, seq, ack, flags)` 的固定流程：

1. `ttl <= 0` → 丢弃，记 `DROP_TTL`；
2. 查路由表，无表项 → `DROP_NO_ROUTE`；
3. `resolve(当前节点, 下一跳)`（可能 +2 tick）；
4. 建帧（CRC-8）→ 链路判定（丢包 → `DROP_LOSS`；误码 → `DROP_CRC`）；
5. 若下一跳 == 目的 → `DELIVER`；否则 `ttl -= 1`、`now += link.delay`、记 `FWD`，回到 1。

- 实测：A→C 转发 **2 跳**；TTL 归零被丢；误码帧被 CRC 丢弃。
- 转发是**逐跳重新建帧**（MAC 每跳改写），IP 层字段不变（除 TTL）。
  这与真实路由器一致，也是"MAC 只在一段链路上有效"的教学点。
- 简化：不做分片/重组（`IPv4-FRAG` 只是枚举占位，无实现）、不做 MTU、不做 ICMP。
  MTU 缺失意味着"大包被静默送达"，教学上必须说明真实网络会分片。

## 6. 校验、丢包与重传（L6c）

### 6.1 校验

| 层次 | 手段 | 覆盖 | 检出能力 |
|---|---|---|---|
| 帧 | CRC-8 | 帧头 + 载荷 | 单比特 104/104；双比特未穷举验证 |
| 传输 | 段编号 + 累积确认 | 丢失/重复 | 只检"缺段"，不检"段内损坏"（损坏在帧层已丢） |

> 这是**两级分工**：链路层保证"这一段比特没坏"，传输层保证"这一段没丢"。
> 教学上必须把这两件事分开讲，否则玩家会以为"有 CRC 就不需要重传"。

### 6.2 TCP-lite 状态机（简化）

| 状态 | 事件 | 动作 | 下一状态 |
|---|---|---|---|
| CLOSED | `connect()` | 发 SYN（`flags=0x02`） | SYN_SENT |
| SYN_SENT | 发送成功 | 记录 `next_seq=1` | ESTABLISHED |
| SYN_SENT | 发送失败 | `now += rto`；`rto *= 2`；重试 | SYN_SENT |
| SYN_SENT | 重试 ≥ `max_retries(5)` | 记 `ABORT` | CLOSED |
| ESTABLISHED | `send(data)` | 按 `mss=8` 切段，逐段发送 | ESTABLISHED |
| ESTABLISHED | 单段发送失败 | `now += rto`；`rto *= 2`（上限 `rto₀·2^max_retries`） | ESTABLISHED |
| ESTABLISHED | 单段重试耗尽 | 记 `ABORT` | CLOSED |
| ESTABLISHED | `close()` | 发 FIN | FIN_WAIT |
| FIN_WAIT | — | 本规格不做收尾握手（记缺口） | TIME_WAIT（占位） |

参数：`rto=10`、`max_retries=5`、`window=4`（段）、`mss=8`（字节）。
实测（链路丢包率 0.45，发 5 段）：

| 指标 | 实测 |
|---|---|
| 送达段数 | 5 |
| 重传次数 | 12 |
| 同一段内退避链 | `10 → 20 → 40`（严格递增，段间 RTO 重置） |
| 场景回放哈希 | `805627a7cc13f777` |
| 重试耗尽 | 5 次后 `ABORT`，状态 `CLOSED` |

**必须写进 UI 的三条简化**（见 7.3）：

1. 本实现**没有对端接收器**：`connect()` 只发 SYN，发送成功即视为"建立"，
   没有 SYN-ACK 回程；`ack` 字段只是发送端本地记账。
   → 玩家看到的是"超时重传曲线"，**看不到**真正的三次握手报文交换。
2. 每段独立计时、串行发送，**没有**滑动窗口流水线、没有乱序缓存、没有 SACK、
   没有拥塞控制（cwnd 恒为 1）。
3. 重传是"整段重发"，没有快速重传（三次重复 ACK）这一课。

> 为什么这样简化：把"可靠传输"的**因果链**（丢 → 等 → 超时 → 退避 → 重发）
> 单独抽出来教，比塞进一个真 TCP 实现更清楚；真 TCP 的窗口/拥塞控制需要
> 几十个交互参数，玩家会看不到因果。代价是玩家学不到流水线与拥塞控制。

## 7. 简化影响表（必须与 UI 说明一致）

| # | 简化项 | 真实做法 | 为什么简化 | 对教学的影响 |
|---|---|---|---|---|
| 7.1 | MAC 8 位、点对点链路 | 48 位、共享介质/交换机 | 省掉冲突域与转发表 | 学不到 CSMA/CD、广播风暴；**不影响**"下一跳解析"结论 |
| 7.2 | CRC-8 | CRC-32 | 事件成本与示教清晰度 | 检出能力不能外推到真实链路；**不影响**"校验→丢帧"结论 |
| 7.3 | 段编号 + 无对端 ACK | 字节编号 + 双向状态机 | 因果链更清晰、确定性更好 | 看不到真实握手/窗口；**不影响**"超时→退避→重传"结论 |
| 7.4 | 集中式 Dijkstra 收敛 | 分布式协议逐轮收敛 | 玩家一次就看到"最终表" | 学不到收敛过程；计数到无穷另用 DV 实验补偿 |
| 7.5 | 无 MTU/分片/ICMP | 有 | 减少分支 | 大包"总能送达"是错的；必须在关卡文案标注 |
| 7.6 | 无 ARP 老化/欺骗 | 有 | 减少状态 | 学不到 ARP 安全；不影响缓存/下一跳 |
| 7.7 | 无 NAT/DHCP/端口语义 | 有 | 与"从零建网"主题无关 | 接真实电脑那一关必须由桥接层承担（见 01 第 9 节） |

**判定原则**：简化只允许削掉"分支与参数"，不允许削掉"因果"。
凡是削掉了因果的（如 7.3 的对端 ACK），必须在 UI 上显式说明"这里省略了回程"。

## 8. 确定性（网络层专用）

- 每条链路一个独立 RNG，种子 `splitmix64(world_seed ^ link_id)`；
  RNG **只在发送点消耗**，且消耗顺序固定为 `loss → corrupt → 翻位位置`。
- 因此"同一场景同一 seed 两次运行"哈希必须一致：实测
  `688b3f0adafb3a4b`（两次相同）；换成 seed 12 得 `33a52bb0647e8818`（不同），
  证明随机性真实生效而不是被写死。
- `now` 是整数毫秒 tick，推进只由"发送/送达/超时"事件驱动，**禁止每帧轮询**。
- 回放 = 事件流 `(now, tag, detail)` 的规范化串 + 场景输入日志（02 第 8.2 节）。

## 9. 本层已知缺口（诚实清单）

1. 没有拥塞控制、没有流水线窗口，因此**不能**用本层演示"吞吐随丢包下降"。
2. 没有真实握手回程，因此"SYN 洪泛/半开连接"这类安全课不能做。
3. 没有分片/重组与 MTU 发现，因此"大包在窄链路失败"不能演示。
4. 没有无线信道模型（衰落/干扰/隐藏终端），丢包是常数概率注入。
5. 没有时间同步（NTP），所有节点共用一个整数时钟。

以上四条若要在后续关卡补，必须新增**独立仿真模块**，不得偷偷改本层的语义
（那会让 08 的 golden 全部失效）。
