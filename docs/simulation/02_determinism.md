# 02 确定性、时间模型与存档/回放

**硬性要求**：`相同世界种子 + 相同输入序列 + 相同引擎版本` ⇒ `逐 tick 相同的状态序列`。
跨机器、跨帧率、跨存档、跨"快进/慢放"都必须成立。做不到的地方要显式降级（见第 9 节），
不允许"大部分时候对"。

## 1. 时间基

- 唯一时间单位：**整数 tick**，从 0 开始单调递增。
- 1 tick 定义为 **1 个归一化反相器延迟**，与真实工艺无关。
  示波器横轴可以选择"50 ps / 500 ps / 1 ns 每 tick"的**显示标尺**，
  标尺只影响 UI 文本，**绝不进入仿真状态与存档**。
- 时间推进必须"跳到下一个事件时刻"，**禁止**每 tick 轮询。网络层的毫秒级延迟
  因此不会产生逐 tick 空转（参考实现里链路延迟 1 ms = 20,000 tick，推进仍是 O(事件数)）。
- 帧与 tick 解耦：渲染 60 FPS 时，每帧推进 `k` 个 tick（`k` 由"仿真速度档位"决定，
  默认 1×=4 tick/帧）。`k` 是**输入**，不是状态的一部分；改变 `k` 不改变轨迹。

## 2. 全序（determinism 的核心）

事件队列排序键 **必须**是 `(tick, seq)`：

- `seq` 在入队时由**单线程单调自增**分配，不用对象地址、不用哈希。
- 同一 tick 内先入队者先执行（FIFO within tick），因此"谁先写线网"是可预测的。
- 多线程仿真只允许在**同一 tick 内互不通信的分区**并行；跨分区通信必须走"tick 边界
  屏障 + 固定顺序的消息合并"，否则顺序不确定。

参考实现中的对应位置：[logic.py](file:///D:/ai%20lm/internet_from_zero/docs/simulation/ref/simcore/logic.py) 的 `Engine._heap` 与 `_Event`。

## 3. 禁止清单（踩过就会破坏复现）

| 禁止 | 原因 | 正确做法 |
|---|---|---|
| 遍历 `dict` / `set` 决定行为 | 顺序依赖实现版本 | 先按键排序，或用稳定索引数组 |
| 用 `time.Now()` / 帧号做随机种子 | 不可复现 | 世界种子派生 |
| 全局 RNG | 子系统互相干扰 | 每实体每流独立 RNG |
| 浮点累加时间 | 跨平台舍入差异 | 整数 tick |
| 用 `float` 表示概率阈值 | 同上 | 整数千分比比较 |
| 帧率决定步长 | 30/60/144 FPS 轨迹不同 | 固定 tick 步进 |
| 事件"来不及就跑一半" | 状态被截断 | 预算耗尽则暂停并明确提示 |

## 4. 传播延迟模型：传输 + 惯性过滤

本模型不是"理想零延迟"，也不是"纯传输延迟"，而是**带惯性过滤的传输延迟**：

1. 输入变化 → 该门在 `t + delay` 排一次求值；
2. 求值时读取**当前时刻**的输入值；
3. 若输出与当前值相同则无事件（自然合并）。

由此得到的物理行为（已实测，见 08 的"冒险"用例）：

- 路径偏斜 **小于** 门延迟时，窄脉冲被**滤除**（真实 CMOS 也是如此）；
- 路径偏斜 **大于** 门延迟时，出现可见毛刺（静态 1 冒险 `F = A·C + B·C'`，
  偏斜 4 tick、或门延迟 3 tick → 实测输出 `1→0→1`）。

**这是特性不是缺陷**。教学上必须同时演示"偏斜 1 tick 被滤除"与"偏斜 4 tick 可见"，
否则玩家会形成"理论冒险 = 一定能看到"的错误直觉。

## 5. 竞争与冒险的处理策略（三档，玩家/教师可切）

| 档位 | 行为 | 适用 |
|---|---|---|
| `EXPLAIN`（默认教学档） | 毛刺照常出现，示波器高亮并计入 `glitch_count` | 讲冒险、讲同步设计必要性 |
| `SYNC`（同步档） | 组合输出只在时钟边沿被采样；毛刺不影响寄存器 | 组装 CPU、总线 |
| `MASK`（工程档） | 宽度 < `pulse_threshold` 的脉冲不写线网（显式参数，非偷偷过滤） | 大规模场景省事件 |

**竞争（race）不等于冒险**：多个驱动源同时写同一线网 → 结果 **X** + `ERR_BUS_CONTENTION` 事件。
引擎不得"最后写的赢"——那会让玩家学到错误的总线行为。

**多时钟域**：跨域采样一律按异步处理（可能 X），要消除 X 必须显式插入同步器（两级 DFF）。
这是真实芯片的做法，也是本作要教的东西。

## 6. 亚稳态

- 建立时间 `setup=2 tick`、保持时间 `hold=1 tick`、`clk_to_q=2 tick`（可配，但进入存档）。
- 违例时 Q 变为 `X`，并写 `METASTABLE` trace；**不猜测**"大概率是 0"。
- 提供可选"物理概率模式"：用实体 RNG 决定最终稳定到 0/1（概率 P），
  但该模式下 **RNG 状态必须进存档**，否则回放不一致。默认关闭。
- 已被验证：4 位计数器组合路径 24+7=31 tick，时钟周期 10 → 实测出现 `0X00`/`XX01`；
  周期 100 时 0..15 全部正确（08 用例）。

## 7. 随机性

- 世界种子 `world_seed: u64`。
- 派生：`stream_seed = splitmix64(world_seed ^ fnv1a(entity_id) ^ (stream_id << 32))`。
- 随机流按用途分离：`LINK_LOSS`、`LINK_CORRUPT`、`METASTABLE`、`MAP_GEN` ……互不共享。
- 判定用整数：`rng.next_u32() % 1000 < permille`。**禁止** `random()` 浮点比较。
- 参考实现用 `random.Random(f"{seed}:{a}:{b}")`，语义等价于"按链路分流"，但生产实现应换成
  可序列化的 PCG/xoshiro，并把内部状态写入存档。

## 8. 存档 / 回放格式（建议实现方案）

采用 **快照 + 输入日志** 双层，两者都可独立校验。

### 8.1 快照（`.ifzsnap.json`，可 gzip）

```json
{
  "format": "ifz-sim/1",
  "engine_version": "1.3.0",
  "tick": 123456,
  "world_seed": 987654321,
  "display_scale": "1ns/tick",
  "wires": {"clk": "0", "alu.y[3]": "1", "...": "..."},
  "regs": {"pc": 7, "acc": 15, "flags": {"Z":0,"C":0,"V":0,"N":1}},
  "memory": [[0, 18], [1, 51]],
  "timers": [{"at": 123460, "handler": "clk.rise"}],
  "next_seq": 4242,
  "digest": "sha256:...."
}
```

规则：
1. `wires` 与 `regs` 的键**必须排序**后写出（canonical JSON）。
2. 只允许出现整数/字符串/布尔；**没有浮点**。
3. `timers` 只允许"可由配置重建的定时器"（时钟、RTO、ARP 老化）；
   任意闭包不得进入存档 —— 生产实现用 `handler_id` + 参数表。
4. `digest` = 对"去掉 digest 字段的规范化 JSON"做 SHA-256。
5. 存档只允许在**事件队列不包含待执行的组合事件**时进行：
   即"时钟边沿已处理完、组合逻辑已 settle"。若在毛刺中途存档，恢复后的波形会不同，
   必须拒绝（参考实现 `Circuit.snapshot()` 在队列非空时直接抛错）。

### 8.2 回放（`.ifzreplay.jsonl`，逐行）

```
{"t":0,"k":"input","d":{"wire":"switch.1","v":"1"}}
{"t":40,"k":"input","d":{"wire":"switch.2","v":"1"}}
{"t":1000,"k":"checkpoint","d":{"digest":"sha256:...."}}
{"t":2000,"k":"assert","d":{"pc":9,"acc":15}}
```

- 回放 = 从初始状态 + `world_seed` 重跑输入日志，任何 `checkpoint` 的 digest 不匹配即失败。
- 输入按 tick 排序；同一 tick 多个输入按文件顺序应用（顺序即语义）。
- 录制时必须记录**帧率无关**：只写 tick，不写帧号。

### 8.3 版本策略

| 变更 | 动作 |
|---|---|
| 仅 UI/文案 | `engine_version` patch +1，存档兼容 |
| 增加器件/字段（有默认值） | minor +1，旧档可读，新档旧版本不可读 |
| 改变任何延迟常量/排序规则 | **major +1**，旧档作废，golden 全部重录 |

golden 用例的哈希必须进仓库（`ref/verify_report.md` 已自动生成哈希一栏）。

## 9. 已知的非确定性来源（诚实清单）

1. **Python 字典顺序**：参考实现里 `wires` 的遍历在 `snapshot()` 中已排序；
   但 `Circuit.history` 是同 tick 内的真实顺序，不能用于跨实现比对。
2. **多线程分区合并**：若实现方采用分区并行，跨区消息必须按 `(src_partition, seq)` 排序
   再合并；否则同 tick 顺序会漂移。
3. **GDScript 的 `Array.sort()` 稳定性**：不要依赖，排序键必须唯一（加 seq）。
4. **浮点显示**：示波器把 tick 映射到像素时可用浮点，但**不得回写状态**。
5. **概率模型开关**：打开亚稳态概率模式后，RNG 状态必须存档；否则同一存档回放会漂移。

## 10. 验收方法（可执行）

- 同一场景跑两遍：比较 `(tick, kind, subject, payload)` 规范化串的 SHA-256 前 16 位。
- 参考实现已验证：TCP 丢包场景同 seed 两次哈希一致 `688b3f0adafb3a4b`，
  seed 12 得到 `33a52bb0647e8818`（不同即说明随机性确实生效，而不是被写死）。
- 快进测试：以 1 tick/帧与 500 tick/帧分别跑到同一 tick，状态 digest 必须相同。
- 存档测试：`snapshot → restore → 继续跑` 与"不存档直接跑"的后续 digest 必须相同。
