# 05 加密（从凯撒到公钥的抽象阶梯）

对应实现：[crypto.py](file:///D:/ai%20lm/internet_from_zero/docs/simulation/ref/simcore/crypto.py)。

## 0. 唯一不可协商的结论

> **游戏内所有自制加密都只能教"机制"，不能教"安全"。**

原因不是"做得不够好"，而是结构性限制：

1. 游戏必须确定性可复现（02 第 7 节），因此**没有真随机源**。
   没有真随机就无法实现"数学上安全"的一次性密码本。
2. 教学场景要求密钥空间小到"能在一屏里穷举"，这直接摧毁强度。
3. 自制算法没有经过密码分析，**不能**用"我们设计了它"来替代"它被验证过"。

所以本规格给出的不是"加密系统"，而是**一条可以走完的抽象阶梯**：
每一级都要求玩家亲手把它破掉，从而理解"下一级为什么存在"。

## 1. 阶梯总览

| 级 | 机制 | 密钥空间 | 破解成本（实测/理论） | 教学结论 |
|---|---|---|---|---|
| C0 | 凯撒（移位） | 26 | 26 次穷举，毫秒级 | 单表替换 = 无安全性 |
| C1 | 单表替换 | 26! | 频率分析，几十字符 | 密钥空间大 ≠ 安全 |
| C2 | 一次性密码本（OTP） | `2^(8n)` | 数学上不可破（**前提**：真随机、等长、一次性） | 唯一"可证明安全"的古典构造，但游戏内做不到 |
| C3 | Feistel 玩具分组 | `2^8 = 256` | 256 次穷举，256 分组全双射已实测 | 混淆+扩散的结构；**不是** DES/AES |
| C4 | 教科书 RSA | `n = 3233` | 试除瞬间分解为 53×61 | 公钥/私钥不对称的数学；**不是**可用加密 |
| H | 哈希（FNV-1a / SHA-256） | — | FNV 非密码学；SHA-256 仅作校验 | 哈希 ≠ 加密 ≠ 签名 |

> 阶梯的价值在于**每一级都能被上一级的工具打破**：C0 用穷举、C1 用统计、C2 用"密钥复用"
> （见 4.2）、C3 用穷举、C4 用分解。玩家不是"被告知不安全"，而是"亲手算出来不安全"。

## 2. C0 凯撒（关卡：第一次"看不懂的纸条"）

- 输入：可打印 ASCII 中的字母（非字母原样保留）；参数：`shift ∈ [0,25]`。
- 输出：密文；**无密钥管理**（shift 直接就是密钥）。
- 破解接口 `caesar_break_bruteforce(cipher)` 返回 **26 个候选**（含 shift=0）。
  实测：26 个候选、可自动定位正确 shift=3。
- UI 必须同时展示 26 行候选，而不是只显示正确答案 —— 让玩家看见"穷举"这个动作。
- **禁止文案**："加密成功""已保护"。

## 3. C1 单表替换（关卡：频率分析）

本规格只给结论，不给参考代码（不在 ✅ 器件范围内）：替换表 = 26 个字母的排列，
密钥空间 26! ≈ 4×10^26，但自然语言冗余使"几十个字符"即可用频率分析攻破。

- 教学点：**密钥空间不是强度**。这条比任何公式都重要。
- 游戏内不实现统计引擎（那不是仿真核心），但关卡数据可以提供"字母频率直方图"供玩家点选。

## 4. C2 一次性密码本（关卡：理论上完美的方案，为什么用不了）

### 4.1 结构

`cipher = msg XOR key`，要求 `len(key) == len(msg)`，`key` 只用一次。

- 实测：往返正确（roundtrip = true）。
- 这是唯一"信息论安全"的对称构造。**但**：

### 4.2 游戏内的致命前提（必须讲）

| 前提 | 真实世界 | 游戏内 | 后果 |
|---|---|---|---|
| 密钥真随机 | 物理熵源 | 由 `world_seed` 派生 | 密钥可被"读存档"得到 |
| 密钥等长 | 真 | 真 | 可满足 |
| 密钥只用一次 | 真 | 玩家常复用（演示） | 复用后 `c1 XOR c2 = m1 XOR m2`，统计可分离 |

- 实测：`key_reuse_leaks = true`（两段密文异或后能看出明文结构）。
- **结论**：游戏内的 OTP 是"OTP 的结构"，**不是**"OTP 的安全性"。
  任何情况下不得标注为"安全"，只能标注"信息论安全的前提在这里不成立"。

## 5. C3 Feistel 玩具分组密码（关卡：把"混淆+扩散"做成机器）

| 参数 | 值 | 说明 |
|---|---|---|
| 分组 | 8 位（L/R 各 4 位） | 小到能在一屏显示全部状态 |
| 轮数 | 4 | 能看出"单轮不够，多轮才扩散" |
| 轮密钥 | 2 位/轮（共 8 位密钥） | 密钥空间 256 |
| 轮函数 | `F(rk, x) = rot3((x·0x1B + rk) mod 256)` 取低 4 位 | 故意设计成可预测，**不提供任何强度** |

- 加/解密：`(L,R) → (R, L XOR F(R,rk))`，逆变换用相反轮序（已修正并验证）。
- 实测：`keys=256 × blocks=256` 全组合**双射**（256 个密钥都是置换）；
  穷举破解：密钥空间 256，命中 **16** 个候选（因为轮函数对部分密钥退化，
  16 个密钥给出同一密文）→ 这本身就是一堂课：**"唯密文攻击可能有多个解"**。
- **禁止**在 UI 或剧情里称其为 DES/AES 或"现代加密"。
  正确表述："这是 DES 的骨架（Feistel 网络），但 DES 的强度来自 56 位密钥与 16 轮
  以及经过几十年攻击验证的 S 盒，这些都不在这里。"

## 6. C4 公钥（关卡：不用先共享密钥）

- 玩具 RSA：`p=61, q=53, n=3233, φ=3120, e=17, d=2753`。
- 实测：`pow(pow(42,e,n),d,n) = 42`；试除分解得 `(53, 61)`，耗时毫秒级。
- 教学点（按顺序）：
  1. 加密用公钥、解密用私钥 → **不对称**；
  2. 不对称来自"分解 n 很难"，而不是"算法复杂"；
  3. 本关的 n 小到能当场分解 → 强度 = 数学难题的**规模**，不是算法名字；
  4. 教科书 RSA **无填充** → 相同明文得相同密文（确定性），可被比对；
     真实实现必须用 OAEP 等填充，本规格不做。
- UI 必须显示"把 n 分解给你看"的按钮。**禁止**出现"安全""无法破解""军事级"。

## 7. H 哈希（关卡：校验 ≠ 加密 ≠ 签名）

| 函数 | 用途 | 强度声明 |
|---|---|---|
| FNV-1a 32 | 存档校验、去重、哈希表 | **非密码学**，可碰撞，禁止用于签名/口令 |
| SHA-256 | 存档 digest、回放校验 | 密码学哈希，但**不是加密**（不可逆、无密钥） |

- 实测：`fnv_differs = true`（雪崩不保证，仅演示"改一位就变"）、`sha256_len = 64`。
- 教学点：哈希提供**完整性**，不提供**机密性**，也不提供**身份**（那需要密钥/MAC/签名）。

## 8. 游戏内强度边界（写死的红线）

| 声明 | 判定 |
|---|---|
| 凯撒/替换/维吉尼亚 可被破 | ✅ 允许且必须演示 |
| OTP 结构可实现，但游戏内**不安全** | ✅ 必须这样说 |
| Feistel 玩具 = 结构演示，**强度为零** | ✅ 必须这样说 |
| 玩具 RSA = 数学演示，**强度为零** | ✅ 必须这样说 |
| "我们自制了一个安全加密" | ❌ **禁止** |
| "用这个算法保护你的通信" | ❌ 禁止（除剧情反讽且紧跟"它已被破"） |
| "军事级/银行级/无法破解" | ❌ 绝对禁止 |
| 引用 AES/RSA-2048 作为"现实中的强度参照" | ⚠️ 允许，但必须标注"本游戏未实现，也不验证" |

**实现边界（技术侧）**：

- 游戏内可以使用：XOR、置换、Feistel 结构、模幂、哈希（作为校验）。
- 游戏内**不得**：自实现可用于生产的分组密码/AEAD、自实现密钥交换并宣称安全、
  把 `world_seed` 派生的密钥当作真随机。
- 若后续关卡真要"安全通信"，唯一诚实做法是**调用宿主平台的标准库**
  （经 L7 桥接），并在 UI 明确"这一段由宿主 TLS 提供，游戏内只做转发"。

## 9. UI 文案禁则（给文案/本地化同学的清单）

禁词：`安全`、`加密后无法破解`、`军事级`、`银行级`、`不可攻破`、`绝对`、
`保护你的隐私`（除非紧接"这里其实保护不了"）。

必须出现的一行（每关加密相关面板底部）：

> 本关演示的是机制。这里的所有方案都能被上面的工具破开；
> 现实中的安全依赖密钥长度、随机源与经过验证的实现，不依赖"自己设计的算法"。

## 10. 确定性说明

- 加密模块**无随机**（除 OTP 密钥由 seed 派生）→ 同一 seed 同一明文同一密文。
- 因此"相同明文得到相同密文"在本游戏内**恒成立**，这本身就是教科书 RSA/ECB 的弱点演示，
  必须在 C4 关卡里明确说明"这不是巧合，而是缺陷"。
- 若未来引入"随机填充"，填充源必须走 02 的 RNG 分流并进存档，否则回放会漂移。
