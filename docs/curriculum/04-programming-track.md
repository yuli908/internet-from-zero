# 编程课程体系：汇编 → C → Java → Python → Web 国际象棋

> 定位：语言线不是"四门语言课"，而是**四次工程能力升级**。每门语言都在回答上一阶段暴露的问题；答不上"为什么现在学它"，就不开这门课。
> 前置：第 3 章（CPU/ISA）之后进汇编；第 6、7 章（网络/可靠传输）之后才允许写联网项目。
> 与主线的关系：语言线是主线的一部分，不是选修；但允许玩家在第 14 章前只精通其中两门。

---

## 1. 设计原则

1. **痛点驱动**：先让玩家在上一阶段真实受苦（比如手写机器码改一个常量要重排地址），再引入新语言作为"止痛药"。
2. **一门阶段只主修一门**：同时开两门语言，初学者会把语法差异当成原理差异。
3. **每门语言必须落到一个真实项目**：自动化、爬虫、游戏、后端四类载体至少覆盖两类，不允许"只做课后小题"。
4. **概念螺旋回收**：指针、栈、并发、协议、内存，每门语言都用不同抽象再讲一次，并明确对照"上一门语言里它长什么样"。
5. **能力不可伪造**：每门语言的验收都要求"能运行、能测试、能解释失败"，不接受选择题通关。

### 1.1 四阶段衔接总表

| 阶段 | 上一阶段暴露的痛点 | 本语言提供的解法 | 代价（必须讲） | 载体项目 |
|---|---|---|---|---|
| 汇编 | 高级语言"看不见机器"，CPU 章只跑微指令，玩家不知道程序真身 | 直接控制寄存器/内存/栈，看见每条指令的代价 | 可读性差、可移植性为零、开发慢 | 串口回显、排序、启动代码 |
| C | 汇编无法维护、无类型、无复用 | 结构化控制流、函数、类型、可移植、贴近硬件 | 手动内存、UB、构建复杂 | 系统工具、TCP 客户端、嵌入式固件 |
| Java | C 的内存与工程化灾难：泄漏、越界、多人协作无约束 | 自动内存、强类型、包与接口、成熟并发/网络库 | 启动重、GC、样板代码、抽象泄漏 | 并发对局服务器、后端 API |
| Python | Java 的仪式感太重，脚本/数据/实验迭代慢 | 动态类型、REPL、极简语法、海量库、胶水能力 | 运行慢、类型错误后置、GIL、依赖管理 | 自动化巡检、爬虫、AI 原型、棋类 AI |
| Web 交付 | 程序只在终端里跑，无法给别人用 | 浏览器 + 协议 + 前后端，把前面所有层串起来 | 前端/网络/部署复杂度 | 网页国际象棋 |

> 教学禁令：不要在 C 阶段讲"Java 有 GC 所以不用学指针"；也不要在 Java 阶段说"Python 更简单所以 Java 没用"。每次切换都要**保留旧语言的价值**，否则玩家会认为前面白学。

## 2. 汇编（第 9 章，5 节）

### 2.1 为什么这个阶段用汇编

- 玩家刚亲手造完 CPU，此时"程序"还是拨码开关和微指令。汇编是**人与机器之间的第一份合同**：指令怎么编码、寄存器怎么命名、栈怎么长。
- 只有在这里，玩家才能理解"C 的指针不是魔法，是一个地址加上类型"；否则后面讲指针只能靠比喻。
- 汇编也是**调试能力的分水岭**：会看寄存器/栈帧的人，后面学任何语言都更快。

### 2.2 覆盖范围

| 模块 | 必须覆盖 | 明确不讲 |
|---|---|---|
| 指令编码 | 操作码/寄存器号/立即数/寻址位；RISC 与 CISC 差异一句话 | 具体厂商指令手册全表 |
| 寄存器 | 通用/栈指针/帧指针/标志寄存器；调用者保存 vs 被调用者保存 | 向量寄存器细节 |
| 寻址 | 立即、寄存器、直接、间接、变址、PC 相对 | 段式寻址历史 |
| 控制流 | `cmp/test` + 条件跳转；有符号/无符号边界 | 分支预测细节（第 3 章已提） |
| 栈与调用 | 参数传递、返回地址、栈帧、16 字节对齐（System V AMD64 为例）；Windows x64 影子空间只提一句 | 异常展开/unwind 细节 |
| 中断/IO | 中断向量、保存/恢复现场、内存映射 IO、轮询 vs 中断 | 完整驱动框架 |
| 工具 | 汇编器、链接器、调试器（单步/断点/看寄存器/看栈） | 手写 ELF 解析器 |

### 2.3 真实项目载体

1. **串口回显**（必做）：中断接收字节、回显、处理溢出。对应第 11 章嵌入式的前置肌肉记忆。
2. **字符串排序**（必做）：50 行以上，含循环、比较、交换、函数调用。
3. **启动代码**（选做）：设置栈指针、清零 `.bss`、跳转到 main；让玩家看见"C 程序启动前发生了什么"。

### 2.4 常见坑（教学重点）

| 坑 | 现象 | 根因 | 教学对策 |
|---|---|---|---|
| 寄存器被踩 | 调用返回后值莫名改变 | 没遵守调用者/被调用者保存约定 | 在函数入口显式 push/pop，并在调试器逐帧核对 |
| 栈不对齐 | 调用 `printf` 崩溃或行为异常 | `call` 前栈指针未 16 字节对齐 | 画栈图，标 `rsp mod 16` |
| 标志位用错 | 有符号比较用了无符号跳转 | `jg` vs `ja` 混用 | 用负数/大数边界各测一次 |
| 循环差一 | 数组越界或少处理一个元素 | 计数与下标混用 | 用"首/末/空"三组用例 |
| 字节序 | 多字节数据读写颠倒 | 小端存储 | 用内存窗口观察字节顺序 |
| 手写机器码错位 | 指令长度算错，后续全乱 | 立即数字节数/前缀 | 先汇编器生成，再手工对照，不一开始手写全部 |

### 2.5 验收

- 能独立写 ≥50 行汇编并通过测试；
- 能在调试器里说出每个寄存器的含义；
- 能解释"函数调用时栈里每一格是什么"；
- 能把一段 C 编译成汇编，指出优化前后的差异（不要求会写优化）。

## 3. C（第 10 章，7 节）

### 3.1 为什么这个阶段用 C

- 汇编解决了"看见机器"，但暴露"人不能这样写大型程序"。
- C 是**少数同时满足"贴近硬件、可移植、能写操作系统/嵌入式/网络栈"的语言**，正好承接第 3 章 CPU 与第 11 章嵌入式。
- C 的指针/内存模型是后面所有语言的"底图"：Java 的引用、Python 的对象、Go 的切片，都可以对照 C 讲。

### 3.2 覆盖范围

| 模块 | 必须覆盖 | 库/工具 |
|---|---|---|
| 类型与表达式 | 整型/浮点/字符/布尔；整型提升；有符号/无符号；`sizeof`；溢出 UB | `<stdint.h>`、`<limits.h>` |
| 控制流/函数 | 分支、循环、递归、值传递、作用域、生命周期 | — |
| 指针与数组 | 指针算术、数组退化、字符串、函数指针、`const` | `<string.h>` |
| 结构体/联合/位域 | 对齐、填充、内存布局、位操作 | `<stddef.h>` |
| 动态内存 | `malloc/calloc/realloc/free`；泄漏、悬垂、双重释放 | `<stdlib.h>`、ASan/Valgrind |
| 预处理器/构建 | 宏、条件编译、头文件保护、多文件、静态库、链接 | `gcc/clang`、`make`/`cmake` |
| 标准 IO | 文件、格式化、错误处理、缓冲 | `<stdio.h>`、`<errno.h>` |
| 系统接口 | 文件描述符、`fork/exec`（可选）、socket、`poll` | POSIX、`<sys/socket.h>`、`<pthread.h>` |
| 调试 | 断点、watch、core dump、ASan/UBSan | gdb/lldb |

### 3.3 真实项目载体

1. **系统巡检工具**（必做）：读 `/proc` 或自建虚拟文件，统计 CPU/内存/磁盘，输出 JSON；练文件 IO、字符串、错误处理。
2. **TCP 客户端**（必做）：连接第 6 章自建服务器，处理粘包/半包；练 socket 与协议分帧。
3. **嵌入式固件雏形**（必做，接第 11 章）：GPIO 点灯 + 串口上报。
4. **简易内存分配器**（选做）：用空闲链表实现 `malloc/free`，理解碎片；不做也可，但作为"进阶挑战"。

### 3.4 常见坑

| 坑 | 现象 | 根因 | 教学对策 |
|---|---|---|---|
| 未定义行为 | 本地正常、换机器崩溃 | 越界、溢出、悬垂、未初始化 | 每章配 ASan/UBSan 实验，要求"先复现再修" |
| 数组退化 | `sizeof(arr)` 在函数里变成指针大小 | 数组传参退化为指针 | 传长度参数；用结构体包数组 |
| `malloc` 大小错 | 分配 `sizeof(ptr)` 而非 `sizeof(*ptr)` | 类型混淆 | 统一写 `sizeof *p` |
| 字符串无终止 | `strlen` 越界/乱码 | 忘记 `\0` | 用 `snprintf`，禁用 `gets` |
| 有符号/无符号比较 | `-1 < 0u` 为假 | 整型提升 | 打开 `-Wsign-compare` |
| 头文件重复包含 | 重定义错误 | 缺 include guard | 统一模板；讲编译/链接流程 |
| 链接顺序 | 符号未定义 | 静态库顺序敏感 | 画"编译→链接→加载"流程图 |

### 3.5 验收

- 多文件项目一条命令构建；
- 1000 条消息的分帧客户端无丢失/错序；
- ASan 干净；
- 能解释"这段代码在什么输入下会 UB"。

## 4. Java（第 12 章，6 节）

### 4.1 为什么这个阶段用 Java

- C 暴露了三类灾难：内存错误、多人协作无约束、并发原语太底层。
- Java 用**自动内存 + 强类型 + 包/接口 + 成熟并发库**把这三件事工程化；它是"长期运行、多人维护"的第一次体验。
- 第 14 章的五子棋服务器需要并发与网络，Java 是最合适的"工程化训练场"；Python 太随意，C 太危险。

### 4.2 覆盖范围

| 模块 | 必须覆盖 | 库/工具 |
|---|---|---|
| 语言基础 | 类/对象/接口/记录类；泛型；枚举；异常；Lambda | `java.lang` |
| 集合 | `List/Map/Set/Deque`；复杂度；`equals/hashCode` 契约 | `java.util` |
| IO/NIO | 字节/字符流、缓冲、文件、`Path` | `java.io`、`java.nio.file` |
| 并发 | 线程、`ExecutorService`、`ConcurrentHashMap`、`CompletableFuture`、happens-before | `java.util.concurrent` |
| 网络 | `Socket`/`ServerSocket`、HTTP 客户端 | `java.net`、`java.net.http` |
| 工程 | Maven/Gradle、JUnit 5、日志、依赖管理 | Maven/Gradle、JUnit、SLF4J |
| 运行时 | 类加载、双亲委派、分代 GC、JFR/GC 日志 | `javac`、`java`、JFR |
| 数据 | JDBC/SQLite（可选）、JSON | JDBC、Jackson |

### 4.3 真实项目载体

1. **对局服务器**（必做）：房间管理、并发对局、断线重连、协议编解码；直接服务第 14 章五子棋。
2. **后端 API**（必做）：HTTP 接口 + 校验 + 日志 + 测试；练工程化。
3. **棋类规则引擎**（必做）：五子棋/国际象棋规则、合法性校验、胜负判定；要求 30+ 测试用例。
4. **压测与故障注入**（必做）：50 连接、随机断线、慢客户端；观察线程池与背压。

### 4.4 常见坑

| 坑 | 现象 | 根因 | 教学对策 |
|---|---|---|---|
| `==` vs `equals` | 字符串比较偶尔错 | 引用比较 vs 值比较 | 统一用 `equals`；讲字符串常量池的"偶尔对" |
| `hashCode` 契约 | `HashMap` 取不到 | 重写 `equals` 没重写 `hashCode` | 用可变对象做 key 的实验 |
| 自动装箱缓存 | `Integer(127)==Integer(127)` 为真，128 为假 | 缓存区间 -128..127 | 强制用 `equals` 或基本类型 |
| 并发可见性 | 压测偶发卡死/读到旧值 | 缺 happens-before | 用 `volatile`/锁/并发容器三版对比 |
| 死锁 | 两线程各持一把锁 | 锁顺序不一致 | 统一锁序；用线程 dump 定位 |
| GC 停顿 | 高峰期延迟尖刺 | 分配率过高/堆配置不当 | 读 GC 日志；减少临时对象 |
| 依赖冲突 | `NoSuchMethodError` | 多版本传递依赖 | `dependency:tree`；锁定版本 |
| 受检异常滥用 | 到处都是 `throws` | 异常当控制流 | 分层：可恢复 vs 编程错误 |

### 4.5 验收

- 50 并发对局 10 分钟无死锁；
- 断线 30 秒内恢复；
- `mvn test` 在干净环境通过；
- 能读懂一次 GC 日志并说出至少一个优化点。

## 5. Python（第 13 章，6 节）

### 5.1 为什么这个阶段用 Python

- Java 的工程纪律必要，但"验证一个想法"太重：写个脚本要建工程、编译、配依赖。
- Python 提供**最快的反馈回路**，适合三件事：自动化（把系统黏起来）、采集（把网页变数据）、原型（把 AI/算法先跑通）。
- 但必须明确：Python 不是"更简单的 Java"，它是**另一种取舍**——用运行期灵活换开发速度，代价是类型错误后置、性能与 GIL 限制。

### 5.2 覆盖范围

| 模块 | 必须覆盖 | 库/工具 |
|---|---|---|
| 语言基础 | 数据结构、推导式、切片、迭代协议、异常、上下文管理器 | 内置 |
| 函数工具 | 闭包、装饰器、生成器、`functools/itertools` | 标准库 |
| 工程化 | 包/模块、`venv`、`pyproject.toml`、依赖锁定 | `pip`、`uv`/`poetry` |
| 文件/系统 | `pathlib`、`os`、`subprocess`、日志、`argparse` | 标准库 |
| 网络采集 | `requests`、`BeautifulSoup/lxml`、限速、重试、robots | 第三方 |
| 并发 | `asyncio`、`aiohttp`、线程池；GIL 边界 | 标准库 + `aiohttp` |
| 数据 | `json`、`sqlite3`、`csv`；`pandas`（可选） | 标准库 / 第三方 |
| 测试/交付 | `pytest`、打包、容器化 | `pytest`、Docker（可选） |
| 游戏/AI | `pygame`（原型）、`python-chess`、minimax | 第三方 |

### 5.3 真实项目载体

1. **自动化巡检**（必做）：定时检查服务/磁盘/证书，异常发通知；练 `subprocess`、日志、重试。
2. **爬虫**（必做）：抓取**自己搭建的网站**（不抓外部站点，避免法律与反爬问题），解析、去重、落库、限速。
3. **游戏设计原型**（必做）：用 `pygame` 做五子棋/贪吃蛇原型，验证规则与手感；再迁到 Java 服务器与 Web 前端。
4. **异步采集器**（必做）：`asyncio` 并发抓 100 个 URL，对比串行耗时，解释 GIL 适用边界。
5. **棋类 AI**（必做）：minimax + alpha-beta，接第 14 章网页国际象棋。

### 5.4 常见坑

| 坑 | 现象 | 根因 | 教学对策 |
|---|---|---|---|
| 可变默认参数 | 多次调用共享同一个 list | 默认值只求值一次 | 用 `None` + 函数内初始化 |
| 闭包晚绑定 | 循环里的 lambda 全用最后一个值 | 延迟绑定 | 用默认参数或 `functools.partial` |
| 浅拷贝 | 改副本影响了原对象 | 嵌套可变对象 | 讲 `copy.deepcopy` 与不可变设计 |
| GIL 误解 | 多线程 CPU 密集不提速 | GIL 限制字节码并行 | 用 `multiprocessing` 或 C 扩展；讲 I/O 密集例外 |
| 依赖地狱 | 换机器跑不起来 | 未锁版本/全局安装 | `venv` + 锁文件；CI 复现 |
| 阻塞事件循环 | async 里调用同步 IO，全部卡住 | 未用 `run_in_executor` | 用 `asyncio.sleep` 与同步调用对比实验 |
| 异常吞掉 | 出错但静默 | `except: pass` | 禁止裸 except；要求日志 |
| 浮点精度 | 0.1+0.2≠0.3 | 二进制浮点 | 用 `decimal`/整数分；讲适用场景 |

### 5.5 验收

- 干净机器一条命令跑通测试；
- 爬虫 100 页无重复、限速生效、失败可重试；
- 异步版显著快于串行，并能说清"什么时候不该用 async"；
- 棋类 AI 不作弊、能在限定时间内出招。

## 6. 终局：网页上运行的国际象棋

### 6.1 为什么是国际象棋，而不是继续做五子棋

- 五子棋是**网络线**的验收：证明自制协议能支撑实时对局（第 14 章主线）。
- 国际象棋是**语言线**的验收：规则复杂度足够高（王车易位、吃过路兵、升变、将军/将死、逼和），能逼出真正的规则引擎、测试用例、AI 搜索与前后端分工。
- 两者不互相替代：五子棋证明"能连"，国际象棋证明"能交付一个别人愿意用的软件"。

### 6.2 目标形态

- 浏览器打开即玩，无需安装；
- 支持人机对战与双人联网；
- 规则引擎通过 30+ 用例（含所有特殊规则）；
- AI 有难度分级，且**不读取对手内部状态**；
- 部署在玩家自己重建的网络上（至少经过一次真实 IP/端口/NAT）。

### 6.3 架构分层与语言分工

| 层 | 职责 | 语言/技术 | 对应前序章节 |
|---|---|---|---|
| 规则引擎 | 合法走法、将军、将死、逼和、特殊规则 | 先 Python 原型，后 Java 重写（对照两种实现） | 第 3 章状态机、第 12 章 OOP |
| AI | minimax + alpha-beta + 评估函数 | Python（原型）/ Java（线上） | 第 13 章 AI、第 3 章性能 |
| 服务端 | 房间、匹配、计时、断线重连、观战 | Java（线程池 + WebSocket） | 第 12 章并发、第 7 章可靠传输 |
| 协议 | 走法消息、状态同步、心跳、重连 | JSON over WebSocket；自定义帧格式对照 | 第 6 章 HTTP、第 7 章握手 |
| 前端 | 棋盘渲染、拖拽、合法落点提示、音效 | HTML/CSS/JS + Canvas | 第 14 章 Web 交付 |
| 部署 | 端口映射、DNS、TLS、日志 | 玩家自建网络 + 反向代理 | 第 8 章 TLS、第 14 章排障 |

### 6.4 实施阶段（每阶段可独立验收）

1. **规则引擎（单机）**：Python 实现 + `pytest` 用例；覆盖王车易位、吃过路兵、升变、三次重复、50 步规则。
2. **AI**：minimax + alpha-beta；深度可调；局面评估（子力 + 位置表）；限时出招。
3. **服务端**：Java 重写规则引擎（或调用 Python 服务），房间与并发；协议先跑通"双人同机"。
4. **前端**：Canvas 棋盘、拖拽、合法落点、悔棋请求、计时器；先本地对 AI。
5. **联网**：WebSocket 状态同步、断线重连、观战；跨机对战。
6. **真实网络**：经过 NAT/端口映射/DNS/TLS；抓包证明"真的走出去了"。

### 6.5 验收用例（规则引擎，节选）

| 用例 | 期望 |
|---|---|
| 王车易位：路径被攻击 | 不允许 |
| 吃过路兵：仅立即下一步有效 | 过期不允许 |
| 升变：四种棋子 | 全部可选，且状态正确 |
| 将军：不能自杀式解将 | 拒绝非法走法 |
| 将死 vs 逼和 | 正确区分 |
| 三次重复局面 | 判和（按约定规则） |
| 50 步无吃子无兵动 | 判和（按约定规则） |
| 非法输入/乱序消息 | 服务端拒绝且不断线 |

### 6.6 常见坑（跨语言项目）

| 坑 | 现象 | 根因 | 对策 |
|---|---|---|---|
| 规则引擎两端不一致 | 前端允许、后端拒绝 | Python/Java 两份实现漂移 | 以测试用例为唯一契约；两端跑同一套 |
| 时钟/网络延迟 | 玩家"超时"误判 | 客户端计时 vs 服务端权威 | 服务端为权威，客户端只显示 |
| 重连状态丢失 | 断线后棋局错乱 | 只同步增量、未同步全量 | 重连时下发全量快照 + 版本号 |
| AI 超时 | 复杂局面卡死 | 未设搜索上限 | 迭代加深 + 时间预算 |
| 前端卡顿 | 每步重绘整盘 | 无脏矩形/离屏画布 | 分层 Canvas/局部重绘 |
| 部署失败 | 本机通、外网不通 | NAT/防火墙/端口 | 按第 14 章排障清单逐项 |

## 7. 教学法与节奏

### 7.1 每门语言的"三遍法"

1. **读**：读一段可运行的、略高于当前水平的代码，能说出每一行在做什么；
2. **改**：在给定代码上做 3 个受控修改（加功能、改边界、修 bug）；
3. **写**：从空文件实现一个小项目，允许查文档，不允许抄完整答案。

### 7.2 每次切换语言的"痛点清单"（必须先由玩家自己说出）

- 汇编 → C：改一个常量要重排地址；没有类型，全靠注释；无法复用。
- C → Java：内存错误难查；多人改同一份代码冲突；并发原语太底层。
- Java → Python：写脚本要建工程；实验迭代慢；胶水代码太长。
- Python → Web：程序只能自己看；别人无法访问；没有界面。

### 7.3 禁止事项

- 禁止在同一章同时教两门语言的语法对比；
- 禁止用"某语言已死/最好"作为选型理由；
- 禁止只讲语法不写项目；
- 禁止把框架当语言教（先懂 socket，再懂 Web 框架）；
- 禁止跳过测试直接讲部署。

### 7.4 与其他章节的衔接

- 汇编必须晚于第 3 章（否则玩家不知道寄存器是什么）；
- C 的 socket 项目必须晚于第 6、7 章（否则不知道协议在干什么）；
- Java 并发必须晚于第 7 章（否则不懂"为什么要重传/超时"）；
- Python 爬虫只抓**自建网站**，且必须讲 robots、限速与法律边界；
- Web 国际象棋必须晚于第 8 章（TLS）与第 14 章前半（真实网络排障）。
