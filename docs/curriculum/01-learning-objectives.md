# 学习目标矩阵（全主线）

> 文档性质：教学目标合同。供教学设计、关卡设计、程序实现三方共用。
> 原则：**每条目标必须能被观察、被判定**。凡不能判定者，一律改写或删除。
> 适用版本：Godot 4.4.1 原型期课程基线。修改本表需同步修改 `03`（练习）与 `06`（评估）。

---

## 0. 本文档怎么用

1. 关卡设计按 `LO` 编号建任务，任务卡上标 `LO`，不标"第几关"。
2. 程序实现按"验收证据"列写自动化测试或人工验收清单，不按"知识点"写。
3. 评估系统按 `LO` 累计掌握度（见 `06-assessment-and-feedback.md`），章节通关以 `LO` 为单位，不以"题目做完"为单位。
4. 任何新增知识点，先回答：它归属哪条 `LO`？若没有，则要么新增 `LO`，要么不进游戏。

## 1. 五档能力定义

| 档位 | 名称 | 定义 | 允许的考核动词 | 证据形式 | 不合格表现 |
|---|---|---|---|---|---|
| L1 | 知道 | 能识别、命名、复述，不需要推理 | 识别、指出、命名、复述 | 单选/配对/连线，无提示正确率 ≥ 80% | 需要看提示才能认出；名称与符号对不上 |
| L2 | 理解 | 能用自己的话解释、举新例、指出反例、在另一种表征中辨认同一概念 | 解释、举例、比较、指出反例、换图 | 口述/短文 + 至少一个新例子 + 至少一个反例；换表征题正确 | 只会背原文；换个说法就认不出；举例只会用课上原例 |
| L3 | 能算 | 能按规则独立计算、推导，并展示中间步骤 | 计算、推导、标注、判断 | 限时独立完成 ≥ 4/5，且中间步骤可读 | 结果对但步骤无法解释（疑似猜的）；边界情况全错 |
| L4 | 能做 | 能在游戏内搭建、调试、实现，并通过黑盒验收 | 搭建、实现、调试、修复、测量 | 黑盒用例全过 + 无提示完成 + 存档可复现 | 照着攻略点完但换个输入就错；离开提示就停手 |
| L5 | 能迁移 | 在未教过的新情境中组合运用，能说明方案取舍并预测失效条件 | 设计、迁移、权衡、预测、批判 | 变式题（未教过的组合）+ 说明两种方案的代价 + 预测一个失效场景 | 只会套用模板；无法说出"什么时候它会坏" |

### 判定与升级规则

- **L1 不单列目标**：每节的知识点清单即 L1 范围，由章测的记忆题抽样验收。
- **L4 是硬门槛**：任何 `LO` 标 L4，必须有游戏内可搭/可调/可运行的证据，不接受纯答题。
- **L5 只给关键目标**：全表 98 条中 17 条为 L5（17.3%），避免"人人都要迁移"的虚高要求。
- **章节通关线**：本章 L1–L3 目标全绿 + L4 目标通过率 ≥ 70% + 章测 ≥ 70 分。三者缺一不算通关，但**不阻断主线**，只标记"待补"（见 `06`）。
- **档位可降不可跳**：若玩家 L3 不稳，不允许用 L4 的"照着做"通过来冒充掌握。

### 档位与题型对应

| 档位 | 首选题型 | 不适用题型 |
|---|---|---|
| L1 | 记忆题（单选、配对） | 开放题 |
| L2 | 理解题（解释、找反例、换图） | 纯计算 |
| L3 | 计算题、读图题 | 口头感想 |
| L4 | 搭建题、调试题、实现题 | 单选 |
| L5 | 开放题、迁移题、权衡题 | 有唯一答案的题 |

## 2. 主线结构与前置依赖

### 2.1 三条纵线 + 两条横切能力

- **物理线**：电平 → 二进制 → 布尔 → 门 → 组合 → 时序 → 寄存器 → ALU → CPU/ISA。
- **网络线**：信号完整性 → 线路编码/成帧 → 分层寻址 → 路由转发 → 可靠传输 → 应用协议 → 接入真实互联网。
- **语言线**：机器码/汇编 → C → Java → Python → Web 交付。
- **横切 A：调试与测量**（万用表、逻辑探针、示波器、抓包、断点、日志）贯穿全程，不单独成章。
- **横切 B：验证与文档**（真值表、波形、方案卡、测试用例、协议对照表）贯穿全程。

### 2.2 依赖图（`→` 表示"必须先于"）

```
[第1章 电平/二进制/布尔/门/信号/半加器]
        │
        ├──────────────► [第4章 链路：编码/成帧/校验]
        │                        │
        ▼                        ▼
[第2章 晶体管/锁存器/触发器]   [第5章 分层/寻址]
        │                        │
        ▼                        ▼
[第3章 组合/时序/ALU/CPU/ISA] [第6章 交换/路由/NAT/DNS/HTTP]
        │                        │
        │                        ├────────► [第8章 密码学/TLS]
        │                        ▼
        │                 [第7章 可靠传输]
        ▼
[第9章 汇编] ──► [第10章 C] ──┬──► [第11章 嵌入式]
                              │
                              ├──► [第12章 Java] ──► [第13章 Python]
                              │                              │
                              └──────────────► [第14章 终章：hi, human + 五子棋 + 网页国际象棋]
```

**跨线约束（容易排错的地方）**

- 第4章（链路）只依赖第1章，可与第2、3章并行；但**第6章必须先于第7章**，否则"路由"和"端到端重传"会被混成一件事。
- 第8章（加密）放在第6章之后、第7章前后皆可；本课程放在第7章之后，因为 TLS 需要"可靠传输"的语境。
- 第11章（嵌入式）紧跟第10章（C），因为嵌入式是 C 的"真实世界出口"；不放到最后，避免玩家以为 C 只为考试存在。
- 第12、13章顺序不可颠倒：Java 先建立工程化与并发纪律，Python 再讲"快速与胶水"，否则玩家会把 Python 的随意当成工程标准。

### 7.2 已知取舍（诚实记录）

1. **数学前置未单列**：对数（信息量）、集合（布尔对应）、二进制运算需要初中以上数学。若目标用户更年轻，需在第 1 章前加 20 分钟"必需数学"微课，本表暂不单列 `LO`。
2. **操作系统概念分散嵌入**：进程、文件描述符、虚拟内存没有独立章节，分别在第 10、12 章以"够用即止"的深度出现。这是刻意取舍，避免主线膨胀；代价是玩家对"操作系统"缺少整体图景，第 14 章需补一张总图。
3. **L5 占比 17.3% 偏高**：主要落在"权衡/排障"类目标。若实测劝退率高，优先把 LO-6.3、LO-7.7、LO-10.8 降为 L4（保留题目但不作为通关门槛）。
4. **"为什么是二进制"存在争议**：本课程**不采纳**"计算机只懂 0 和 1"这类拟人化解释，采用"工程选择 + 路径依赖"的诚实解释，并明确给出三进制计算机与多电平闪存两个反例。详见 `02-chapter-01-teaching-script.md` 第 1.2 节。
5. **五子棋与网页国际象棋是两个终局**：五子棋是"网络线"的验收（证明自制协议能支撑实时对局）；网页国际象棋是"语言线"的验收（规则引擎 + AI + Web 交付）。两者不互相替代，见 `04-programming-track.md` 第 6 节。
