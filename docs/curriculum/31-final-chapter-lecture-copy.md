## 0. 口径

- **终章结构不同于 lab 页，故不套 `after` 序列。** 本文件按 02 §4 与大纲的三子目标（F1 出网 / F2 五子棋 / F3 凭证）编排，每个子目标有独立讲解、独立实践产出、独立判定与独立存档点；不使用 `{"order","after","title","text"}` 的 5 段节结构，`segments` 只表示讲解顺序。
- 字数沿用前章：每段 **≤150 字**（去半角空格），gate 页中栏 ≤170 字/段；因无 `after` 分档，**同屏合计不适用**，每子目标按 3 段顺序播放。
- 每子目标按 3 条 required 编排（A 为 P5 实践、B 为负例、C 为复算）；**不设 quiz**，避免用选择题替代真实出网、真实对局与真实凭证。若数据侧要求追加 quiz，另加即可，不影响本文件段数与文案。
- **code 只用已存在的**：3 / 7 / 9 / 10 / 13 / 14，不新开任何码。9 为 `E_DELAY_MISMATCH`（时延不符），仅用于「送达/续局超时」判据；其余用 3（未接）、7（表格错）、10（输出不符）、13（覆盖不足）。**未采用 12**（不在白名单，且 12 指「尚未封装」，指不到「没接线 / 固定文案 / 凭证哈希写死」）；15/27 虽在白名单，语义不适用，本文件不采用。
- 端口 `127.0.0.1:7777`、对手端形态（HTML 或可执行小程序）、凭证的具体字段格式**均为 02 的【假设】或未定项**，一律写「以数据侧为准」，本文件不拍数值、不编造 UI 与 API 名；凭证只承诺 02 写明的「时间 / 拓扑 / 程序哈希」三项。
- 本章是 **MUST**（02 §4），前置 CH19 + CH17 + CH10（三条链路都必须通），90 min；三个子目标各自独立存档点，任一失败不推翻其他两个。

## 0.1 三条接缝（写进正文，不是建议）

**接缝 1：F1 的世界出口挂在 19.5 的基站、17.3 的双客户端与 10.4 的可靠传输上，只做最后一跳到本机 TCP。**
出口不是另一套协议栈：游戏内链路把数据送到 World Port，World Port 再落到本机 `127.0.0.1:7777`（端口可配）。违反了会出什么事：游戏内演示与真实流量两套，`hi, human` 可以只在游戏里打印，F1 的「真实网桥」承诺落空。

**接缝 2：F2 的五子棋协议复用 17.1 的消息格式与 17.3 的双客户端，棋子与规则只是负载。**
落子、胜负、悔棋都在你的程序里判定，传输仍走「类型/长度/负载/时间戳」；不新造报文头，不新造传输层。违反了会出什么事：对局在本地自说自话，协议无法被对手端复核，终章的对局证据是假的。

**接缝 3：F3 的凭证复用 18.3 的哈希，对「时间 + 拓扑 + 程序哈希」做摘要，不新造信任模型。**
凭证要能打开、字段要能读出、哈希要能复算；改一处内容，摘要必须变。违反了会出什么事：凭证只是一张截图文字，谁都能改，通关凭证没有可核对象。

## 4. 收束与总验收

- **三个子目标独立存档**：F1、F2、F3 各自有存档点；任一失败不推翻其他两个，对局中断可续（02「失败可恢复」原文）。
- **三条链路都必须通**：CH19 的基站、CH17 的聊天链路、CH10 的可靠传输；缺一条，F1 的出口就只是游戏内装饰。
- **总验收三条同时**：①本机终端收到非固定的 `hi, human`；②一盘五子棋完整结束并判出胜负；③凭证可打开且哈希可复算。三条全过才算通关；任一条只做演示，不给过。
- **幕 V 的一句话**：我接回来了。接回来的不是一根线，是从门、到协议、到世界出口的一整条路。
- 本文件**不把**三子目标合并成一次大验收，也**不把** F1–F3 写成 CH19 的附加节；它们各自是终章的一个单元。
