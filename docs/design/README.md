## 0. 一句话设计定位

> **把一台计算机和一张互联网，从一块电池开始，亲手重造一遍；最后一刻，你的程序真的把「hi, human」发到了玩家自己的电脑上。**

定位补充（写清楚边界，避免后续各自脑补）：
- 这不是「模拟器套皮」。所有玩法机制都要求有可运行的底层模型：电 → 逻辑 → 时序 → 指令 → 包 → 应用。
- 这不是「科普视频」。教学只作为入口，每节都必须有**玩家动手产出 + 机器验收**。
- 这不是「沙盒自由建造」。有明确主线，分支用于发散，技能树始终可见。

## 5. 术语（先统一，避免三个角色各说各话）

- **电平（level）**：物理电压值 `V ∈ [0, 3.3]`，不是布尔值。布尔值是对电平的**判读结果**。
- **判读（read）**：把电平映射为 `0 / 1 / X`（X = 不确定）。阈值见 02 §7。
- **器件（device）**：电路图上的一个可放置对象（有端口、有延迟、有配方、有价格）。
- **子电路（subcircuit）**：玩家把若干器件打包成的可复用黑盒；可展开查看内部。
- **模块（module）**：官方给的大颗粒子电路（ALU、寄存器堆）。
- **整机（machine）**：有面板与外部接口的成品（CPU、显示器、路由器）。
- **产物（artifact）**：玩家在章节里做出的、写入存档的成果，分硬件产物与代码产物。
- **验收（gate）**：机器自动判定的测试，不是「点下一步」。见 06 §4 测试台。
- **蓝图（blueprint）**：可复制的设计（含器件布局+接线+参数），是设计系统的核心资产。
- **自造（craft）**：用已有器件 + 工序 产出新器件，成本约为买价的 70%。
- **走过的路**：技能树上所有已验收节点的持久高亮，**不因章节切换而重置**。

## 6. P0 不可破坏约束（任何方案冲突时，本表优先）

1. **真实机制**：每章产出必须过测试台。禁止用贴图动画、脚本演出替代机制。
   - 四类测试器：逻辑测试（真值表）、时序测试（波形/边沿）、协议测试（报文比对）、程序测试（输入输出样例）。
2. **存档与工程文件不可丢**：
   - 存档格式：单文件 `.ifz`（JSON + `schemaVersion` + 校验和）。
   - 自动快照：每 5 分钟 1 次，保留 3 份轮转 + 1 份「章节通关前」手动锁存。
   - 迁移：任何新增物件/字段必须带 migration 函数；**每次内容上线必须跑旧存档加载回归**（09 §M4 gate）。
   - 禁止：静默丢字段、按名字索引改为按数组下标而不做迁移。
3. **技能树常驻**：任何场景（电路视图 / 代码视图 / 网络视图 / 商店 / 设计台）都可在 ≤1 次操作内打开技能树，并高亮当前所在节点。
4. **可读性**：1080p 下正文最小字号 20 px，等宽数值最小 18 px；正文对比度 ≥ 7:1；**禁止**把关键信息塞进 12 px 小字或仅用颜色区分。
5. **美术语言统一**：全部物件使用「基础几何 + 文字标签」同一套语言；不允许某个层级突然换成写实贴图。
   - 色板（低饱和、硬朗，6 色）：底 `#14161A`、面板 `#1E2126`、主文字 `#E8E6E1`、次文字 `#9A9C9F`、信号/正向 `#B08D3F`、错误/危险 `#A8514B`、信息 `#5B7C8D`（信息色为第 7 个，仅用于连线状态，可裁剪）。
6. **发散解法**：实践关的验收必须是**行为等价**判定（真值表/输入输出/报文），不得要求与标准答案结构一致。至少 1 个官方「非最优但合法」的示例解。
7. **不写死数值**：所有价格、延迟、阈值以数据表驱动（`04` + `02 §7`），不在代码里散落常量。
