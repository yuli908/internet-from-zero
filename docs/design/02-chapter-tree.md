## 1. 总览

- 5 幕 + 19 章主线 + 1 终章 + 9 分支 + 7 挑战 = **36 个节点**。
- 主线是**窄路**：每一章只强制一条实现路线。分支提供第二/第三条路线与额外物件。
- 必修（`MUST`）= 主线推进必需；选修（`OPT`）= 解锁额外物件/替代路线，不阻塞终章；挑战（`CHAL`）= 无奖励门槛，给硬核玩家。
- 「时长」= 教学 + 实践的中位估计，单位分钟，`【假设】`。必修链（不含 CH13/CH14）合计 ≈ **2 000 min（33 h）**；含两章选修 ≈ 2 185 min（36 h）。

| 幕 | 章 | 主题一句话 | 幕末情绪 |
|---|---|---|---|
| I 电与逻辑 | CH1–CH4 | 从电压到能算加法的机器 | 「我在算」 |
| II 机器 | CH5–CH6 | 从 ALU 到一台能显示字的计算机 | 「我造的」 |
| III 连通 | CH7–CH10 | 从两根线到可靠的端到端传输 | 「它到了」 |
| IV 语言 | CH11–CH15 | 从手写机器码到可调用的接口 | 「我能表达」 |
| V 文明 | CH16–CH19 + 终章 | 从服务到无线，接回真实世界 | 「我接回来了」 |

依赖规则（供程序实现直接落数据）：
- `hard` 前置：必须 gate 通过才解锁（上图实线）。
- `soft` 前置：显示「推荐先完成」但不阻塞（如 CH11 对 CH10）。
- 分支一旦解锁，**永久保留入口**；即使玩家跳过，技能树上仍显示为「可选支路」。
- 挑战关只需其所属章 gate 通过，**不要求**主线推进到当前部位。

## 3. 主线章节规格

> 模板字段：状态 / 前置 / 解锁 / 教学目标 / 核心机制 / 产出物 / 时长 / 验收 / 章末反转。
> 「无条件」= 该章必需、玩家无法跳过；所有 gate 由测试台机器判定（06 §4）。

### CH01 · 第一束电  `MUST`  100 min
- 前置：无。解锁：CH02、C01、C02。分支：无。
- 教学目标：
  1. 能把「电压」读成 `0/1/X`，并说清为什么中间有一段「不许当数」的区间。
  2. 能用 N 个二态开关表示 0…2^N−1，并完成二/十/十六进制互转。
  3. 能用与/或/非组合出任意给定真值表（至少 XOR 一例）。
- 核心机制：电平判读器（带阈值滑块与噪声注入）、开关面板计数、继电器门搭建、示波器（延迟/毛刺）、子电路封装。
- 产出物：`M01 电源`、`M10 开关`、`G01/G02/G03 三色门`、`G04 XOR`、`G12 半加器`、`KN` 若干。
- 时长：100 min（教学 35 / 实践 65）。
- 验收：见 03 全章 gate（6 节各自 gate + 章末集成 gate）。
- 章末反转：拆开自己刚用的继电器与门，看到「它有线圈、会响、会慢」——为 CH2 的晶体管埋钩子。

### CH02 · 沙中之门  `MUST`  85 min
- 前置：CH01。解锁：CH03、B01。
- 教学目标：
  1. 说清 BJT/MOSFET 作为「电控开关」的三端关系，能判读饱和/截止。
  2. 用 NMOS+PMOS 搭出反相器，并解释为什么 CMOS 静态几乎不耗电。
  3. 把 CH01 的继电器门等价替换为 CMOS 门，并测出速度/体积差异。
- 核心机制：器件参数面板（阈值电压、导通电阻、栅极电容【假设】）、功耗与发热可视化、等价替换检查器（真值表等价 + 延迟对比）。
- 产出物：`M06 三极管`、`M07 MOSFET`、`G01–G03` 的 CMOS 版本、`M13 空白 PCB`。
- 时长：85 min（教学 30 / 实践 55）。
- 验收：用 2 个 MOSFET 的反相器在 3 组输入下输出正确；继电器版 vs CMOS 版同一 XOR 的延迟比 ≥ 5×【假设】。
- 章末反转：同样一块板，继电器版塞不进 4 个门，CMOS 版塞得进 20 个 —— 「不是聪明，是便宜」。

### CH03 · 记忆与运算  `MUST`  120 min
- 前置：CH02。解锁：CH04、C03。
- 教学目标：
  1. 区分组合逻辑与时序逻辑，说清「状态」从哪来。
  2. 用 D 触发器搭 8 位寄存器，理解时钟边沿、建立/保持的简化模型。
  3. 用半加器拼出全加器，再用 8 个全加器拼出 8 位行波进位加法器。
- 核心机制：时钟源与分频、边沿触发可视化、行波进位延迟链测量（第 8 位比第 1 位晚多少 t）、总线与三态。
- 产出物：`G13 全加器`、`G14/G15`、`G16 8 位寄存器`、`G18 计数器`、`M11 时钟源`。
- 时长：120 min（教学 40 / 实践 80）。
- 验收：8 位加法器 16 组随机用例全对；寄存器在 10 个时钟周期内稳定保存任意值；进位延迟测量报告生成。
- 章末反转：加法器越宽越慢 —— 为 C03 超前进位与 CH5 的时钟上限埋因。

### CH04 · ALU 与控制  `MUST`  110 min
- 前置：CH03。解锁：CH05、B02。
- 教学目标：
  1. 能用多路选择器把「加法/与/或/异或/取反」汇成一个可切换的输出。
  2. 说清「操作码 → 控制信号」的译码过程。
  3. 理解存储器地址译码与 IO 端口的最小模型。
- 核心机制：8 选 1 多路选择、操作码译码器、SRAM 单元阵列（256×8）、IO 端口映射、控制信号真值表编辑器。
- 产出物：`S01 ALU-8`、`G10/G11 多路选择`、`S03 主存 256B`、`S06 IO 接口`、`S05 控制单元`。
- 时长：110 min（教学 40 / 实践 70）。
- 验收：ALU 对 8 种操作 × 8 组操作数全对；写一个「地址→读出值」的存储器测试；IO 端口写入能点亮对应指示灯。
- 章末反转：ALU 不知道自己在算什么，它只是「被选中的那条路」—— 控制单元才是意志。

### CH05 · 处理器  `MUST`  140 min
- 前置：CH04。解锁：CH06、C05。
- 教学目标：
  1. 说清取指—译码—执行—写回，并能用手动时钟逐刻观察。
  2. 能读懂 `MUD-8` 指令表（§7.5），手写一段 5 条指令的程序。
  3. 理解「时钟频率上限 = 最长组合路径」。
- 核心机制：单周期 CPU 数据通路搭建（PC/IR/寄存器堆/ALU/内存/控制）、手动时钟与自动时钟、指令级单步、首个异常刻定位。
- 产出物：`H01 CPU-MUD8`、`S02 寄存器堆`、`S07 总线控制器`。
- 时长：140 min（教学 50 / 实践 90）。
- 验收：跑通「A=3, B=5, 输出 8」程序；跑通「循环 0..9 累加」；波形中能指出每次取指的刻。
- 章末反转：把时钟从 1 Hz 拉到 100 Hz，程序行为突然错乱 —— 时序余量不是玄学。

### CH06 · 计算机时代  `MUST`  95 min
- 前置：CH05。解锁：CH07、B03、B09（软）。
- 教学目标：
  1. 能用字符显示器 + 键盘构成最小人机界面，理解「显存 = 一块内存」。
  2. 理解程序从「拨开关输入」到「从存储加载」的转变（加载器）。
  3. 说清存储层次（寄存器/内存/外部存储）为什么必须存在。
- 核心机制：字符显存（16×4 字符【假设】）、键盘扫描、扬声器（方波发声）、引导加载器（把纸带/磁带内容读入内存）。
- 产出物：`H03 显示器`、`H05 键盘`、`H04 扬声器`、`H06 磁带机`、`M12 排线`、`P02 加载器`。
- 时长：95 min（教学 35 / 实践 60）。
- 验收：在自制计算机上显示「HELLO IFZ」；键盘输入能改变显存指定格；加载器能从外部存储把程序装入并运行。
- 章末反转：这台机器现在能自己「读程序」了 —— 计算机时代开始，也是你最后一次手动拨开关。

### CH07 · 机器间传比特  `MUST`  110 min
- 前置：CH06。解锁：CH08。
- 教学目标：
  1. 说清并行 vs 串行、同步 vs 异步、波特率与采样时刻的关系。
  2. 能解释「为什么线上传的是电平变化，不是 0 和 1」。
  3. 能设计一个 4 位帧并解释起始位/停止位/校验位。
- 核心机制：线缆模型（延迟 + 噪声 + 串扰【假设】）、UART 发送/接收器（采样时钟偏移演示）、示波器双通道、误码注入。
- 产出物：`M02 线缆`升级件、`H07 网卡（雏形）`、`G20 时钟分频`。
- 时长：110 min（教学 40 / 实践 70）。
- 验收：两台自制机在 9600 bps【假设】下互通一个字节；把采样点故意偏移 30% 后能观察到误码并修正；帧格式检查器通过。
- 章末反转：你以为在传「数据」，其实只是在开关一根线 —— 协议是给「开关」加的意义。

### CH08 · 协议  `MUST`  115 min
- 前置：CH07。解锁：CH09。
- 教学目标：
  1. 说清分层的必要性（每层只解决一件事）。
  2. 能设计一个 3 层最小协议：物理帧 / 寻址包 / 应用消息，并解释封装与解封装。
  3. 理解握手、确认、超时的最小语义。
- 核心机制：协议编辑器（字段定义 + 位宽 + 校验）、封装/解封装可视化（包的一生）、握手状态机、抓包面板。
- 产出物：`P07 TCP/IP 协议栈（初版）`、协议蓝图、`H07 网卡（完整）`。
- 时长：115 min（教学 45 / 实践 70）。
- 验收：同一消息在 3 台节点间转发时字段不被破坏；丢包注入后握手能重试成功；抓包面板能展开每层字段。
- 章末反转：你写的「消息」，在线上被拆成了 3 个信封 —— 从此「应用」和「线」不再知道对方。

### CH09 · 地址与路由  `MUST`  125 min
- 前置：CH08。解锁：CH10、B07、C07。
- 教学目标：
  1. 能解释地址为什么必须唯一，并做子网划分（4 位网络号 + 4 位主机号）。
  2. 能手工维护路由表并解释「下一跳」。
  3. 说清交换机（按 MAC/端口）与路由器（按网络号）的差别。
- 核心机制：地址分配器、路由表编辑器、逐跳可视化（TTL 递减）、交换机转发表学习、环路与广播风暴演示。
- 产出物：`H08 交换机（4 口）`、`H09 路由器`、`B07` 入口。
- 时长：125 min（教学 45 / 实践 80）。
- 验收：4 节点 2 子网全连通；拔掉一条线后路由表在 ≤3 跳内恢复【假设】；广播风暴能复现并被生成树/分区阻断。
- 章末反转：路由器不「知道」互联网，它只知道「下一步交给谁」—— 互联网是无数个「下一步」。

### CH10 · 可靠传输  `MUST`  110 min
- 前置：CH09。解锁：CH11（软）、CH16（软）。
- 教学目标：
  1. 说清「不可靠的链路如何做出可靠的服务」：序号、确认、重传、校验、窗口。
  2. 能解释拥塞/流控为什么要窗口，不只是「发快点」。
  3. 能测量吞吐与重传率，并做一次参数调优。
- 核心机制：可靠通道仿真（丢包率/乱序/延迟可调）、滑动窗口可视化、重传计时器、吞吐仪表盘。
- 产出物：`P07` 完整版（含窗口与重传）、性能报告卡。
- 时长：110 min（教学 40 / 实践 70）。
- 验收：30% 丢包下 1 KB 数据完整送达且顺序正确；把窗口从 1 调到 4 后吞吐提升 ≥ 2×【假设】；人为不确认时能观察到超时重传。
- 章末反转：可靠性不是链路给的，是你**自己花钱买来的**（带宽换确定性）。

### CH11 · 汇编  `MUST`  140 min
- 前置：CH06（硬）、CH10（软/节奏）。解锁：CH12、B04、C02。
- 教学目标：
  1. 能把 `MUD-8` 机器码与助记符一一对应，手写并跑通 10 行以内程序。
  2. 理解跳转、循环、条件标志，能用栈实现一次函数调用。
  3. 能用寄存器/内存面板定位错误。
- 核心机制：汇编编辑器（带行号、错误定位、指令提示）、逐条单步、寄存器/内存/标志面板、断点、栈可视化。
- 产出物：`P01 汇编器`、汇编程序蓝图（可复用）。
- 时长：140 min（教学 50 / 实践 90）。
- 验收：写「1..N 求和」并通过 3 组 N；写「字符串输出」；写一次带栈的函数调用并通过返回地址检查。
- 章末反转：你写的每一行，最终都变成 16 个比特 —— 语言只是给人看的皮。

### CH12 · C  `MUST`  125 min
- 前置：CH11。解锁：CH15、B05、C04。
- 教学目标：
  1. 说清「编译器把表达式变成指令序列」的最小过程（栈式/寄存器式求值）。
  2. 理解指针 = 地址，数组 = 连续地址 + 偏移。
  3. 能解释函数调用约定与栈帧。
- 核心机制：C 子集编译器（`int/char/if/while/函数/指针/数组/printf` 最小集）、编译中间产物查看（AST → 汇编）、内存视图、越界检测。
- 产出物：`P03 C 编译器`、源程序蓝图、`KN` 指针系列。
- 时长：125 min（教学 45 / 实践 80）。
- 验收：3 个基准程序（阶乘/斐波那契/字符串反转）编译后行为正确；指针交换两变量正确；故意越界时给出可读错误而非崩溃。
- 章末反转：`a[i]` 就是 `*(a+i)` —— 没有魔法，只有地址算术。

### CH13 · Java  `OPT`  100 min
- 前置：CH12。解锁：`P04 JVM`（终章可选路线）。
- 教学目标：
  1. 说清「一次编写到处运行」靠的是虚拟机，不是编译器更强。
  2. 理解字节码、栈式 VM、垃圾回收的最小模型（引用计数/标记清扫二选一）。
  3. 能解释对象、引用、继承在内存里长什么样。
- 核心机制：字节码编辑器 + VM 单步（操作数栈可视化）、GC 演示（对象图与回收时刻）、类加载流程。
- 产出物：`P04 JVM`、Java 示例程序。
- 时长：100 min（教学 40 / 实践 60）。
- 验收：跑通一个类 + 继承 + 接口的最小程序；手动触发 GC 并看到对象被回收；字节码与源码逐行对照。
- 说明：本分支存在的意义是「提供第二语言路线」，不阻塞终章。

### CH14 · Python  `OPT`  85 min
- 前置：CH12。解锁：`P05 解释器`（终章可选路线）。
- 教学目标：
  1. 说清解释执行 vs 编译执行的取舍。
  2. 理解动态类型 = 运行时携带类型标签。
  3. 能用脚本把重复劳动自动化（这是它在游戏里的真实价值）。
- 核心机制：解释器（词法→语法→求值）、动态类型标签可视化、脚本自动化接口（可调用游戏内 API 做批量操作）。
- 产出物：`P05 Python 解释器`、自动化脚本（例：批量采购/批量造件）。
- 时长：85 min（教学 30 / 实践 55）。
- 验收：解释器跑通 fib 与列表操作；写一个脚本自动完成 10 次同规格造件。
- 章末反转：语言越「舒服」，机器替你做的事越多 —— 代价是你不再知道它做了什么。

### CH15 · 软件与接口  `MUST`  90 min
- 前置：CH12。解锁：CH16。
- 教学目标：
  1. 说清「接口/库/驱动」三层分工，理解 ABI 与调用约定。
  2. 能把一段可复用逻辑封装成库，并在两个程序里复用。
  3. 理解 socket 抽象：网络在代码里就是「一个能读写的文件」。
- 核心机制：库封装与链接、头文件/接口声明、socket API（open/send/recv/close 映射到自建协议栈）、版本与兼容检查。
- 产出物：socket 库蓝图（`P07` 的前置）、`P10` 前置依赖。
- 时长：90 min（教学 35 / 实践 55）。
- 验收：两个不同程序共用同一个库函数；用 socket 在两台自制机间传一行文本；改库接口后旧程序给出明确兼容错误。
- 章末反转：你一直以为「程序」是完整的，其实它一半是别人写好的。

### CH16 · 服务器  `MUST`  110 min
- 前置：CH15（硬）、CH10（软）。解锁：CH17、B09。
- 教学目标：
  1. 说清「永远在线」意味着什么：监听、多连接、并发、超时清理。
  2. 理解进程/线程与上下文切换的最小模型（或事件循环，二者择一实现）。
  3. 能做一次容量测试：并发 8 连接时延与丢请求率。
- 核心机制：端口监听、连接生命周期、并发模型选择、请求/响应日志、压测面板。
- 产出物：`H10 服务器机箱`、`P08 服务端骨架`、`H12 电源`。
- 时长：110 min（教学 40 / 实践 70）。
- 验收：8 个并发客户端同时请求，全部得到正确响应；杀掉一个客户端后服务端在 ≤5 s 内清理连接；服务端连续运行 10 分钟无内存增长【假设】。
- 章末反转：服务器不是更强的电脑，是「不肯关机的电脑」。

### CH17 · 聊天软件  `MUST`  100 min
- 前置：CH16。解锁：CH18。
- 教学目标：
  1. 能定义应用层消息格式（类型/长度/负载/时间戳）。
  2. 理解「连接状态」：谁在线、消息给谁、离线怎么办。
  3. 能完成一次端到端自测：两个客户端互发并正确显示。
- 核心机制：消息协议设计器、在线状态表、消息队列与投递、客户端 UI 模板（低饱和硬朗、大字号）。
- 产出物：`P09 聊天客户端`、`P08` 完整版、`P13/P14` 前置。
- 时长：100 min（教学 35 / 实践 65）。
- 验收：两客户端互发 20 条消息，顺序与内容 100% 一致；断线重连后未读消息补发；消息长度超限有明确拒绝。
- 章末反转：你写的聊天软件，和三十年前那批人写的，结构几乎一样。

### CH18 · 加密  `MUST`  105 min
- 前置：CH17。解锁：CH19、B06、C06。
- 教学目标：
  1. 说清对称加密（换位/异或流的最小模型）与密钥分发难题。
  2. 理解非对称的用途是「换密钥」而非「加密大数据」。
  3. 理解哈希与签名的区别，能解释中间人攻击为何能成功/被阻止。
- 核心机制：密钥实验台（同一明文不同密钥）、公钥交换演示、哈希雪崩效应、证书链验证器、中间人剧本（可重放）。
- 产出物：`P10 加密库/TLS`、`P11 证书`、加密聊天蓝图。
- 时长：105 min（教学 45 / 实践 60）。
- 验收：无密钥时无法还原消息；中间人剧本在启用证书后被阻断；篡改 1 比特后哈希完全改变。
- 章末反转：加密不是为了藏起来，是为了「让篡改有代价」。

### CH19 · 物联网与无线  `MUST`  130 min
- 前置：CH09（硬）、CH18（软）。解锁：B08、FINAL。
- 教学目标：
  1. 说清「共享介质」带来的冲突，以及 CSMA/退避的直觉。
  2. 理解嵌入式约束：内存小、功耗低、无屏幕、要远程升级。
  3. 能搭一个「传感器 → 单片机 → 无线 → 基站 → 服务器」的完整闭环。
- 核心机制：无线信道（冲突/丢包/信号强度）、CSMA 退避可视化、传感器采样与阈值、低功耗预算表、远程固件升级（失败回滚）、基站接入与多终端调度。
- 产出物：`W01 蓝牙模块`、`W02 传感器`、`W03 遥控器`、`W04 单片机`、`W05 单板电脑`、`W06 基站`、`W07 天线`、`W08 无线终端`、`P12 固件`。
- 时长：130 min（教学 50 / 实践 80）。
- 验收：3 个终端 1 个基站，冲突率 <10% 且全部数据入库；固件升级故意断电后能回滚到旧版本；传感器超阈值触发一次远端告警。
- 章末反转：最后一公里不是线，是空气 —— 而空气不属于你。

## 4. 终章 · `hi, human` + 五子棋  `MUST`  90 min

- 前置：CH19 + CH17 + CH10（三条链路都必须通）。
- 目标（拆成 3 个可独立验收的子目标，避免终局一次性失败）：
  1. **出网**：把自制网络接入「世界出口（World Port）」，向本机打印 `hi, human`。
  2. **对局**：在自制聊天/协议之上实现五子棋协议，完成一盘完整对局（落子合法性、胜负判定、悔棋）。
  3. **证据**：生成一张「通关凭证」（含时间、拓扑、程序哈希），可截图分享。
- 核心机制：
  - **真实网桥**：游戏内协议栈 ↔ 本机 `127.0.0.1:7777`（TCP）【假设端口可配】。玩家需在游戏里显式接线到「世界出口」器件；未接线则不产生任何真实流量（安全与可控）。
  - **对局端**：对手可以是本机上的一个极简客户端（随游戏导出的 HTML/可执行小程序【假设】），玩家在自己程序里实现对局逻辑。
  - **失败可恢复**：三个子目标各自独立存档点；对局中断可续。
- 验收：本机终端收到 `hi, human`（含玩家程序生成的字符串，不是固定文案）；一盘五子棋完整结束并判定胜负；断线重连后能续局。
- 风险提示：这是全项目**技术风险最高**的节点，见 10 §R1。必须最早做技术验证（M1 原型阶段）。

## 7. 底层数值规格（系统仿真直接实现，v0.1 首版值）

> 所有值集中在 `data/balance/*.json`【假设目录由程序实现确定】，本表只给语义与首版默认值。**禁止**在代码中散落魔法数。

### 7.1 电与判读
| 参数 | 值 | 说明 |
|---|---|---|

### 7.2 器件延迟（t 为单位）

|---|---|

### 7.3 时序模型
- 固定 tick 求值：每 t 内「读输入 → 计算 → 排队写回」，避免同刻竞争。
- 触发器：上升沿采样，简化版 setup/hold 为 0；当时钟周期 < 关键路径时**必须**产生可观测错误（用于 CH05 章末反转）。
- 毛刺（glitch）：允许在同一 t 内多次传播，UI 上以波形多跳显示；测试台默认按「稳定值」判定，吊床测试（hazard）关卡单独判定。

### 7.4 信道与网络
| 参数 | 值 |
|---|---|
| 串口速率 | 9600 bps【假设】，可调 1200–115200 |
| 帧格式 | `SYNC(4b=1010) + LEN(4b) + DATA(0..15 nibble) + PARITY(1b)` |
| 包格式 | `DST(8b) + SRC(8b) + TTL(4b) + LEN(4b) + PAYLOAD(≤15B)` |
| 地址空间 | 8 位 → 254 可用节点；子网 = 网络号 4b + 主机号 4b |
| 可靠层字段 | `SEQ(8b) + ACK(8b) + WIN(4b) + CKSUM(8b)` |
| 丢包 | 基线 0%，可调 5/15/30% |
| 无线 | 共享信道，冲突即双方失败；CSMA + 随机退避 0–7 槽【假设】 |

### 7.5 `MUD-8` 指令集（CH05 实现基准）
- 字长：数据 8 位；指令 16 位（`[OPCODE 8b][OPERAND 8b]`）；地址空间 256 B；PC 按字节步进。
- 寄存器：`A`（累加器）、`B`、`PC`、`IR`、`FLAGS(Z,C)`。
- 指令表（16 条，够写求和/输出/五子棋逻辑）：

| 码 | 助记 | 语义 |
|---|---|---|
| 0x00 | `NOP` | 空操作 |
| 0x01 | `LDA a` | `A ← MEM[a]` |
| 0x02 | `STA a` | `MEM[a] ← A` |
| 0x03 | `LDI i` | `A ← i`（立即数） |
| 0x04 | `ADD a` | `A ← A + MEM[a]`，置 Z/C |
| 0x05 | `SUB a` | `A ← A − MEM[a]`，置 Z/C |
| 0x06 | `AND a` | `A ← A & MEM[a]` |
| 0x07 | `OR a` | `A ← A \| MEM[a]` |
| 0x08 | `XOR a` | `A ← A ^ MEM[a]` |
| 0x09 | `JMP a` | `PC ← a` |
| 0x0A | `JZ a` | `Z=1` 时跳转 |
| 0x0B | `JC a` | `C=1` 时跳转 |
| 0x0C | `OUT p` | 端口 `p` ← `A`（1–8 显存/9 键盘/10 网卡） |
| 0x0D | `IN p` | `A ← 端口 p` |
| 0x0E | `LDB i` | `B ← i` |
| 0x0F | `HLT` | 停机 |

- 调用约定（CH11 用到）：`A/B` 传参，返回地址压栈于 `MEM[0xF0..]`【假设】，`Z/C` 不跨调用保存。
