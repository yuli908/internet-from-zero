## 1. 设计系统的定位

> **凡是你「由原理做出来」的东西，都可以回到设计台上再改一遍。**

这不是「编辑器插件」，是主线技能：CH1 的 XOR、CH3 的加法器、CH11 的程序、CH17 的消息格式、CH19 的固件，都必须能在设计 HUD 里打开、改、测、存、上架。

进入方式（三条路径，任一即可）：
1. 在电路视图选中任意自造件 → `E` 进入设计台。
2. 技能树节点右键 → 「在设计台打开」。
3. 商店「我的库」→ 蓝图 → 打开。

## 2. 可重设计的对象类型（5 类）

| 类型 | 对象 | 设计 HUD 里的核心面板 | 典型章节 |
|---|---|---|---|
| D1 子电路 / 器件 | XOR、半加器、全加器、寄存器、ALU | 原理图画布 + 端口 + 器件预算 + 真值表测试 | CH1–CH5 |
| D2 整机 / 面板 | CPU 面板、显示器、路由器、服务器机箱 | 面板布局（接口位置/指示灯）+ 内部槽位 + 散热/功耗预算 | CH5–CH19 |
| D3 代码 / 程序 | 汇编程序、C 程序、协议栈、服务端 | 源码 + 编译产物对照 + 输入输出用例 + 性能计数 | CH11–CH19 |
| D4 协议 / 消息格式 | 帧格式、包格式、聊天消息、五子棋落子协议 | 字段表（位宽/类型/校验）+ 抓包预览 + 兼容性检查 | CH8, CH17, FINAL |
| D5 蓝图（跨对象） | 以上任意组合的成品设计 | 依赖树 + 全量成本 + 一键复现 | 全程 |

不属于设计对象（防止范围失控）：
- 世界地图 / 场景美术 / 剧情文本。
- 已由官方提供的 L2/L3 内部电路（可**查看**，不可改；想改就先自己造一个等价件）。

## 3. 重设计规则（R1–R6，实现时逐条落）

| 规则 | 内容 | 违反时表现 |
|---|---|---|
| **R1 接口冻结** | 重设计默认**不改变端口数量与语义**。要改接口必须显式「升级接口」，此时所有上游引用标记为 `needs_reverify`（黄色叹号），必须重跑一次上游 gate | 直接改端口 → 禁止保存，提示「下游 3 处引用会失效」 |
| **R2 行为契约** | 保存前必须通过本件**既有测试用例集**。允许改变行为，但必须新增用例并标注「非兼容变更」，且该件在商店中标记为 `v2` | 未过测试 → 只能存为草稿，不能上架、不能用于验收 |
| **R3 器件预算** | 受 PCB 等级限制：`PCB-S` 8 器件 / `PCB-M` 24 / `PCB-L` 64【假设】。超预算必须先升级 PCB 或拆分 | 超限时禁止放置，显示「已用 24/24」 |
| **R4 层级隔离** | 设计台内不能引用**当前章未解锁**的器件（防偷跑） | 器件置灰，显示解锁章 |
| **R5 成本透明** | 设计台常驻显示：材料成本、工序数、预计失败率、预计延迟/功耗 | 缺任何一项视为 UI 缺陷 |
| **R6 版本与回滚** | 每件保留最近 10 个版本快照；任意版本可回滚；回滚本身不收费 | 版本丢失 = P0 存档事故 |

设计台的三块固定区域：
```
┌ 左上: 对象身份 (名称/类型/版本 vN/所属章) ┬ 右上: 指标 (成本/工序/延迟/功耗/器件数)
├ 中: 主编辑区 (原理图 / 面板 / 源码 / 字段表) │ 右: 测试台 (用例 + 通过率 + 日志)
└ 底: 对比条 (vN-1 vs vN: 差值箭头)          └ 右下: [保存草稿] [上架] [回滚]
```

## 4. 失败与迭代成本

### 4.1 改动分级与收费（与 05 一致）

| 级别 | 判定 | 花费 | 工序 |
|---|---|---|---|
| L-a 参数级 | 只改阈值、延迟、名称、注释、面板文字位置 | 0 g | 0 |
| L-b 接线级 | 增删连线、调整内部走线、改端口顺序（不改语义） | `0.3 × P` | 1–2 |
| L-c 结构级 | 换器件型号、增删器件、改拓扑 | `0.5 × P` + 新器件用料 | 3–8 |
| L-d 接口级 | 改端口数量/语义 | L-c 费用 + 触发上游复验 | 3–8 |

### 4.2 失败与报废

- 保存时运行测试集：**失败不收费**（只消耗时间），但**上架验证**（跑完整 gate + 抽检）失败按 L-c 结算并报废本次投入的现金（关键件退回）。
- 整机自造（T3/L4）：每 `op` 3% 报废【假设】，见 05 §7。
- **频繁改动保护**：同一件在 10 分钟内第 4 次 L-c 改动起，费用 ×1.5（防「乱试」式穷举，逼玩家先想）。

### 4.3 迭代的正反馈（必须存在，否则玩家不愿改）

- 每次**成功上架**一件 v2+：技能树对应节点获得「迭代」标记，商店回购价 +5%（上限 3 次）。
- 指标优于 v1（延迟 ↓、器件数 ↓、成本 ↓ 任一项 ≥ 10%）：给「优化徽章」，可在 C03/C04 里作为解决凭证。

### 4.4 A/B 测试台（硬需求）

同一组输入同时跑 v1 与 v2，输出一张对比表：

| 指标 | v1 | v2 | 差 |
|---|---|---|---|
| 真值表通过率 | 8/8 | 8/8 | = |
| 稳定延迟 | 6 t | 9 t | +3 |
| 器件数 | 5 | 4 | −1 |
| 材料成本 | 60 g | 42 g | −18 |

判定规则：**行为等价**（`R2`）→ 才允许替换主线在用件，否则只能并存。

## 5. 与商店的联动

| 联动点 | 规则 |
|---|---|
| 上架 | 只有通过完整 gate 的件可上架；上架后出现在「我的库」，价格 = `0.9 × 官方同功能件价`【假设】（自己造的不该比官方贵） |
| 购买 | 可买自己上架的件（等于「让工坊替你做」），成本 = 标价，节省工序 |
| 复制 | 蓝图可复制到同章新位置，成本 = `0.3 × P`（复制不是白拿） |
| 不可售 | `bound`（教学首件）、含未解锁器件的件、`consumed` 件 |
| 商店价格不联动 | 玩家上架价**不影响**官方商店价（05 §7 固定价格锚） |

## 6. 与知识树的联动

- 设计台里能用的器件 = 知识树已点亮节点对应的器件集合（`R4` 的数据来源）。
- 每完成一次「结构级」重设计，对应知识节点增加一条「实现记录」（例：`KN-ADD-02` 记下你用行波进位/超前进位两种实现）。
- 知识卡可反向跳转设计台：「想看这个长什么样」→ 打开官方示例的只读设计台（不可改）。
- 技能树节点显示徽章：`初版` / `迭代 v2` / `优化` / `挑战达成`。

## 7. 验收标准（设计系统本身必须过）

- [ ] 5 类对象各至少有 1 个真实可打开的设计台（CH1 至少覆盖 D1）。
- [ ] R1–R6 六条规则均有可复现的拦截/提示（不是只写在文档里）。
- [ ] 任一重设计可保存草稿、可回滚、可跨存档恢复。
- [ ] A/B 测试台能对同一用例集给出对比表，且「行为等价」判定与 06 §4.4 一致。
- [ ] 上架/购买闭环在 05 的价格体系下不产生套利（用 05 §5.3 三捷径逐条验证）。
- [ ] 指标面板不出现「12 px 小字」；数值用等宽字体。

## 8. 假设
1. 【假设】PCB 等级与器件上限（8/24/64）为可玩性压缩值，非真实工艺。
2. 【假设】上架价为官方同功能件 90%，需实测是否导致「官方商店失效」。
3. 【假设】「10 分钟内第 4 次改动加价」的阈值需按玩家行为数据调整。
