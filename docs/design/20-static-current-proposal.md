# 20 · 器件级静态电流：现状诊断与最小模型提案

> **状态：提案 · 未批准 · 未实施。** 本文档不产出任何代码，也不改 `src/core` 的仿真。
> 对象：`T2.2-3`（lab `inverter`）、`T2.4-4`（lab `replace`），两条当前都是 `E_PENDING(25)`。

## 0. 结论先行

1. 缺的不是一个「Idd 函数」，是两样东西：
   - 仿真层没有任何电流/电荷量（`src/sim/sim_circuit.gd` 只有三值线网 + 整数 tick + 事件堆）；
   - **编辑器没有晶体管级入口**——2.2 的调色板只有 NOT 门（`src/ui/screens/lab_ch02.gd:148`，`:153` 只有一个 NOT 按钮），玩家搭不出「两管同时导通」这种失败结构。
2. 因此只补仿真、不动编辑器的模型（候选 A）会把电流恒算成 0 µA，把 gate 变成**永远通过**——正是 `docs/PROGRESS.md:541` 明令禁止的「假 gate」。
3. 推荐：**不建模型，两条 gate 继续 pending，但把 `pending_reason` 改准**（见 §4）。若产品必须转正，只有候选 B（加晶体管级入口）这一条路，14–18 人日，且成本在编辑器不在模型。

分类结论：

- **有数值、但只是单管单点**：#1、#2、#3、#10。
- **门级算术近似、从不命名电流**：#4（隐含）、#5（其实是动态功耗）。
- **根本没有对应量**：#6（仿真无电流）、#7（有 trace 名无生产者）、#8（死字段）、#9（只做状态降级）、#11（有时钟无电荷）。

一句话：今天的「电流」是**探针读数**（一个管子在一个偏置点的查表值），不是**电路电流**（一个稳态下从 VDD 到 GND 流过的总和）。

### A 的致命问题（为什么不选）

2.2 的编辑器调色板是 `["not"]`（`lab_ch02.gd:148`），`max_gates=4`。玩家搭出的是一张**门图**，每个门都是理想互补单元：

- 稳态下上拉/下拉必有一侧关断 → 电流恒 0；
- 玩家没有任何手段造出「两管同时导通」；
- 于是 `static_current` 判据永远过，玩家永远不知道自己有没有搭对。

2.4（`replace`）同样是门图（等价替换 + 延迟 + 面积），A 算出的 Idd 同样恒 0。

**A 会产出两条永远绿的 gate。** 这比留着 pending 更糟：pending 至少诚实。

### C 的问题

项目只有一种器件模型（三点表），没有第二个实现。为「将来可能换 SPICE/工艺角」先抽接口，就是给死代码加壳——与「不为假设需求造抽象」的纪律冲突。真需要时再抽，成本一样。

## 3. 不可判的下限（写死不做的）

1. **数值精度**：亚阈值漏电、温度、工艺角、W/L、沟道长度调制，都要 SPICE 级求解。三点表只能回答「有没有通路」「是否超过 1 µA」，不能回答「0.37 µA 还是 0.41 µA」。**SPICE 级数值判定永久不做**。
2. **「50 tick 平均 Idd」这个口径本身**：纯稳态下平均 = 瞬时值；有翻转时的平均需要电荷量（C·ΔV），门级仿真没有电容。所以即便做了 B，这个口径也只能落成「稳态直流通路的上限检查」，不是真的平均电流。2.5 的 `αCV²f` 是**公式题**，不能拿来当仿真量。
3. **结论**：能判的上限就是一条布尔——「每个列出的稳态，VDD→GND 直流通路 ≤ 1 µA」。再往下的数值一律不做。

## 4. 两条 gate 的处置（写死）

**继续 pending。** 不转正、不降级、不删。`required` 保持 `true`，仍走 `E_PENDING(25)`，不进分母、不算通过。

但 `pending_reason` 要改口径——现在这句话把缺口说小了（暗示「只是仿真少个公式」）：

- 旧（`data/labs/ch02_labs.json:81`、`:139`）：
  `L1 仿真层只输出逻辑值，无稳态电流模型，规格要求 50 tick 平均 Idd`
- 新：
  `仿真层无电流量，且 2.2/2.4 的编辑器只有门级调色板（lab_ch02.gd:148），玩家搭不出非互补结构；缺口是一层晶体管网表入口，不是单个 Id 公式`

同步位置：`data/labs/ch02_labs.json:81`、`:139`；`data/chapters/ch02_levels.json` 2.4 的 `deferred_reason`（`:33`）；`src/core/ch02_checks.gd:14-16`；`specs/m5/failure_contract.md:244`。

**不降级成别的判据**：门图上任何电流类判据都恒真；降级成 `quiz` 就是拿知识题冒充电路判定（`KN-CMOS-02` 已经覆盖了那个知识点，`data/skilltree.json:45`），同样是假 gate。**宁可 pending，也不发一个永远绿的 gate。**

## 8. 给验收人的一句话

这份提案不产出代码，只回答两件事：**今天的「电流」只是单管探针读数，不是电路电流；而这两条 gate 真正的缺口在编辑器，不在仿真。** 所以推荐继续 pending，而不是先写一个会让 gate 恒绿的电学模型。
