## 1. 双树模型（一张图，两个用途）

| 树 | 回答的问题 | 数据 | 入口 |
|---|---|---|---|
| **技能树**（Progress Tree） | 「我走到哪了？下一步能去哪？」 | 36 个节点 + 依赖边 + 状态 | 顶部条 `技能树 ▸` / `Tab` |
| **知识树**（Codex Tree） | 「这个概念是什么？我当时怎么做的？」 | ~180 张知识卡 + 关联产物 | 技能树节点点开即为知识卡 |

- **共用同一坐标**：技能树是骨架（36 个节点），知识树是挂在节点上的卡片堆。**不做两套独立界面**，避免玩家学两次导航。
- 视觉：横向从左到右 = 时间轴；5 幕 = 5 个纵向分栏；主线 `y=0`，分支在上/下（`y=±1, ±2`）。

## 2. 节点类型（6）

| 类型 | 前缀 | 外观 | 含义 | 数量【假设】 |
|---|---|---|---|---|
| 里程碑 | `CH`/`B`/`C` | 方形块（宽），带章号 | 一章的入口与出口 | 36 |
| 技能 | `SK` | 六边形 | 一种操作能力（会测延迟、会封装子电路、会写循环） | 60 |
| 概念 | `KN` | 圆角卡片 | 一个可查阅的知识点 | 180 |
| 产物 | `M/G/S/H/W/P` | 小方块（内嵌图标） | 做出/买到的实物 | 77 |
| 分支入口 | `B` + 特殊角标 | 虚线方形 | 可选支路，永久保留 | 9 |
| 挑战 | `C` | 菱形（虚线边） | 无门槛目标 | 7 |

## 3. 解锁条件（可被程序直接求值）

```json
{
  "nodeId": "SK-GATE",
  "requires": {
    "all": [
      {"type": "gate", "id": "CH01-G6"},           // 必须通过 CH1 第 6 节 gate
      {"type": "node", "id": "SK-BOOL"},            // 前置节点已点亮
      {"type": "count", "of": "artifact", "tag": "logic", "min": 3}
    ],
    "any": [],
    "cost": {"gold": 0}                             // 可选解锁费（仅分支蓝图）
  }
}
```

规则：
- 条件只允许 `all / any / count` 三种组合，**禁止**嵌套超过 2 层（可维护性）。
- 挑战节点：`requires = 其所属章 gate`，不含任何金币条件。
- 分支节点：`requires` 为前置章 gate，允许在任意后续时间进入。
- 一旦 `completed`，**永不回退**（即使玩家删掉了产物）。产物被删时节点保留，卡片标记「产物缺失，可重做」。

## 4. 四种显示状态与「走过的路」

| 状态 | 视觉 | 连线 | 说明 |
|---|---|---|---|
| `completed` | 暖白实心 + 细金边 | 暖色实线 + 轻微「脚印」纹理 | 走过的路，**永不高亮消失** |
| `available` | 灰底 + 微光描边（呼吸 2 s） | 灰白线，靠近当前处渐亮 | 前方照亮 |
| `locked` | 深灰 + 无描边 | 深灰虚线 | 未解锁，可看名称与解锁条件 |
| `challenge` | 深底 + 虚线边 + 菱形 | 虚线 | 随时可进，不阻塞 |

- **亮度衰减「前方照亮」**：以当前所在节点为中心，`available` 节点按距离衰减（1 跳内 100%、2 跳 60%、3 跳 30%），其余保持最低亮度。数量上限：同时高亮 ≤ 6 个（防噪声）。
- **进度摘要**（树顶部一行）：`已走过 12/36 · 学时 4.2h · 知识卡 38`。
- **当前节点定位**：打开时自动居中并高亮当前章；若玩家在商店/设计台，则高亮「正在操作的对象」。

## 5. 常驻要求（P0）

1. 任何场景 ≤1 次操作可打开（顶部条按钮 或 `Tab`）。
2. 打开为**覆盖层**（不切场景、不暂停仿真、不丢画布选区）。
3. 场景切换（电路/波形/代码/网络）后，树保持上次展开位置与缩放。
4. 关闭后回到原场景原视角（视角容差 0）。
5. 低配机性能：36 节点 + 180 卡片图，首帧打开 ≤100 ms【假设】，主线程无卡顿。

## 6. 知识卡 Schema

```
id             KN-BIN-01
title          二进制：并排的开关
oneLine        每个开关只有两个稳定状态，N 个开关能表示 2^N 个数。
body           ≤600 字，含 1 个例子、1 个数字
misconception  一条常见误解 + 纠正（必填）
figure         可选：几何图示（黑底白线，无贴图）
relatedArtifacts  ["G12","M10"]
relatedNodes   ["SK-BIN","CH01"]
selfTest       1–2 题（选择题或填空），答案折叠
sources        「史实/教材/推导」三类标注；不确定写「假设」
```

硬性：`oneLine` 必须是一句可背诵的结论；`misconception` 必须来自 01 §4 的挫败点清单或实际测试记录。

## 7. 与其它系统的接口

| 系统 | 接口 |
|---|---|
| 设计台（06） | 节点右键「在设计台打开」；结构级重设计成功后写「实现记录」到卡片 |
| 商店（05） | 产物节点显示「价格 / 是否在库 / 可造」三个小标 |
| 引导（08） | 引导脚本只能「指向」节点，不能自动点亮节点（必须玩家真做出来） |
| 存档 | 只存 `nodeId + state + timestamp`，不存渲染数据（避免存档膨胀） |

## 8. 验收标准

- [ ] 36 个章节/分支/挑战节点全部可打开，且解锁条件与 02 §7.6 表一致。
- [ ] 四态显示正确；「走过的路」在重启后仍保持。
- [ ] 从任意场景 ≤1 次操作打开，关闭后视角/选区不变。
- [ ] 知识卡 `misconception` 字段无空缺（教学设计交付时逐一检查）。
- [ ] 点亮节点**只能**由 gate 触发，不可由引导/调试接口直接置位（防作弊与防误触发）。

## 9. 假设
1. 【假设】技能节点 60、知识卡 180 为首版估算，由教学设计按每章 8–12 张填写后回写。
2. 【假设】「脚印纹理」用程序化线条实现，不引入额外美术资源。
